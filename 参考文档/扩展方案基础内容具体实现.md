### 2.2 唯一动流固耦合处：`ApplyObstaclePose` → `ApplyObstaclePoses`

### 2.3 移动推进：`AdvanceObstacle` → `AdvanceObstacles`

```cpp
void AdvanceObstacles() {
    if (!initialized || bodyCount == 0) return;
    float newX[kMaxBodies], newY[kMaxBodies], wallUx[kMaxBodies], wallUy[kMaxBodies];
    bool anyMove = false;
    for (int i = 0; i < bodyCount; i++) {
        // 原 AdvanceObstacle 逻辑套循环：目标逼近 + kMaximumWallSpeed 限速
        // + move/stepsPerFrame 换算
        // ⚠️ 三点必须保留/补齐：
        // 1. 位移≈0 但速度非 0 → 仍要调用一次 ApplyObstaclePoses(x, y, 0, 0)
        //    把壁面速度归零（否则 ghost 格点带着旧速度持续驱动流体）；
        //    该情形 anyMove = true。
        // 2. wallUx[i]/wallUy[i] = 本帧位移 / stepsPerFrame，未移动物体为 0，
        //    绝不能沿用上帧速度。
        // 3. 每物体独立限速 + 独立目标逼近（互不干扰）。
    }
    ResolveOverlapTargets();          // 目标点互不重叠校验（见下）
    // ⚠️ 只校验目标点不够：目标可超前实际位置 kMaximumTargetLead，
    //    拖动快时两物体的"当前位置"可能先于目标重叠。
    //    因此重叠校验必须同时作用于候选新位置 newX/newY（见 §2.3-补足），
    //    仍重叠则拒绝该物体本次移动（保留旧位置与目标）。
    if (anyMove) ApplyObstaclePoses(newX, newY, wallUx, wallUy);
}
```

**§2.3-补足（重叠校验的正确落点）**：`ResolveOverlapTargets()` 只解决"目标点"合法，不能保证"运动轨迹"不重叠。在 `AdvanceObstacles` 计算完各物体 `newX[i]/newY[i]` 后，再对**新位置**做一次两两距离校验：`|(newXi,newYi) - (newXj,newYj)| >= r_i + r_j`；违反的物体直接放弃本次移动（`newX[i] = bodies[i].x` 且保留旧目标），避免两个相向运动的物体穿越彼此。校验失败不应 `return`（其它物体仍可移动）。

**互不重叠校验 `ResolveOverlapTargets()`**（约 10 行）：对每对物体 `i != j`，若 `|t_i - t_j| < r_i + r_j`，把目标点沿连线推回最近合法位置；仍重叠则**拒绝本次目标更新**（保留旧 `tx/ty`）。新物体的添加（§2.5）同样先做该校验，失败则 UI 提示且不添加。

### 2.4 受力分组：`ComputeSolidLoads`（L928-1002）

- 对每个"固体邻居"，先 `owner = OwnerBodyOfCell(...)` 再累加到 `bodyForceX[owner]/bodyForceY[owner]/bodyTorque[owner]`。
- 力矩参考点由固定 `(obstacleX, obstacleY)`（L990-992）改为 `(bodies[owner].x, bodies[owner].y)`。
- 平滑滤波按物体：`bodyForceX[i] += blend * (raw - bodyForceX[i])`。
- `hasMovableObstacle == false` 时清零全部数组（对应原 L930-937 分支）。
  - ⚠️ **门控必须与"可添加物体"能力一致，二选一**：若 §2.5 允许在 Jet（`hasMovableObstacle == false`、`bodyCount == 0`）里添加物体，本分支会把已添加物体的受力清零（逻辑矛盾）。
    - 方案 A（推荐）：物体增删/移动仅当 `hasMovableObstacle == true` 可用（Jet 的 OBJECTS 分组整体禁用），本分支保留"Jet 无物体 → 清零"语义。
    - 方案 B：把门控改为 `bodyCount == 0`，并同步修改 `GetDemoCaseReynoldsNumber` 的特征长度依据（`bodyCount > 0` 时取 `bodies[0].radius`，否则 `jetWidth`）。
  - **每物体平滑滤波**：原单布尔 `hasForceSample` 改为 `bool hasForceSample[kMaxBodies]`，新添加/重置的物体首帧 `blend = 1.0f`，避免从 0 开始平滑导致前几帧力显示偏小。
- 面板只显示 `bodies[selectedBody]` 一组受力，无需 4 行全列。

### 2.5 键盘目标与新增物体

- `UpdateObstacleTarget`(L693-733)：方向键写 `bodies[selectedBody].tx/ty`（margin 沿用原 L715-723）；新增 `Tab` 循环切换 `selectedBody`（配合 `selected` 标志）。
- **添加物体**（UI 触发）：候选位置（如流场中心附近）经**与现有物体当前位置**（`bodies[j].x/y`，而非目标 `tx/ty`）的距离校验（`>= r_i + r_j + 1` 格）后 `bodies[bodyCount++] = 候选`，随后调用一次 `ApplyObstaclePoses` 把新物体写入流场；`bodyCount` 到达 `kMaxBodies` 时 UI 禁用 `+`。
  - ⚠️ 校验对象若写成目标点（`tx/ty`）：因目标可能超前实际位置（`kMaximumTargetLead`），两个"当前已相邻"的物体可能被判合法而重叠。
- **删除物体**：`bodies[i] = bodies[bodyCount-1]; bodyCount--;` 后调用一次 `ApplyObstaclePoses`（该步也负责把被删物体的旧固体格点释放回流体）。
  - ⚠️ **删除后必须维护选中态**：`if (selectedBody >= bodyCount) selectedBody = bodyCount - 1;`（`bodyCount == 0` 时置 -1 并跳过），随后重建 `selected` 标志（仅 `selectedBody` 为 true）。否则后续 Tab / 方向键 / OBJECTS 面板可能越界或操作"幽灵物体"。

### 2.6 绘制：`DrawObstacleTarget` → `DrawBodies`

- 遍历 `bodies[0..bodyCount)`，按 `obstacleShape` 分支绘制轮廓（圆：`GL_LINE_LOOP` 48 段；方形：4 顶点 `(cx±r, cy±r)`；菱形：4 顶点对角线），坐标换算沿用 L1310-1319（除以 `nx-1/ny-1`）。

- 删除 `hasMovableObstacle == false` 的提前返回逻辑中的单物体假设，改为 `bodyCount == 0` 判断。

## 3. 功能 2：鼠标拖动场内物体（多物体）

### 3.1 状态流转（合并进 `WindowProcedure`，消息见 §1.3）

| 事件 | 动作 |
| --- | --- |
| `WM_LBUTTONDOWN` | 若鼠标在 field 内且未被 ImGui 面板捕获 → `PickBody(mouseFieldX, mouseFieldY)`；命中则 `selectedBody = hit`（更新各物体 `selected`）、`dragging = true`、记录 `grabOffsetX/Y = body.xy - mouseFieldXY`、**`SetCapture(window)`**；未命中则 `dragging = false` |
| `WM_MOUSEMOVE` | 更新 `mouseScreenX/Y` 与 `mouseFieldX/Y`；若 `dragging` 且 `!io.WantCaptureMouse` → 写 `bodies[selectedBody].tx/ty = clamp(mouseField + grabOffset)`（clamp 边界沿用 margin = radius+2，见 L715-723） |
| `WM_LBUTTONUP` | `dragging = false`、**`ReleaseCapture()`**（物体保持当前位置，高亮保留） |
| `WM_KILLFOCUS` | `dragging = false`、**`ReleaseCapture()`**（防止鼠标松在外面的残留状态） |

**§3.1-补足（三处必须补齐，否则拖动体验/稳定性有问题）**
1. **SetCapture / ReleaseCapture**：Win32 下按住左键移出客户区后 `WM_MOUSEMOVE` 会停止派发，拖动会"卡死"在最后位置。`WM_LBUTTONDOWN` 命中后必须 `SetCapture(window)`，`WM_LBUTTONUP / WM_KILLFOCUS` 必须 `ReleaseCapture()`。
2. **面板豁免语义统一**（与评估文档 §3.3"拖到 UI 面板上不响应"对齐）：豁免分两级——**新开始的交互**（命中/拾取）要求鼠标在 field 内且 `!io.WantCaptureMouse`；**进行中的拖动**每帧更新目标前也检查 `io.WantCaptureMouse`，为 true（鼠标进入面板控件区）时**跳过本次目标更新**（物体停在当前目标），移出面板后自动继续；拖入面板时不应误触 ImGui 控件。
3. **坐标基准**：每个鼠标消息内先用 `GetClientRect` + `ComputeLayout(width, height)` 得到当前 `layout`，再 `ScreenToFieldPoint`（窗口可能已缩放，不能缓存旧 layout）。

### 3.2 命中检测 `PickBody`

```cpp
int PickBody(float gx, float gy) {
    // 从后往前遍历（后添加者优先），容差 radius + 3 格
    for (int i = bodyCount - 1; i >= 0; i--) {
        const RigidBody& b = bodies[i];
        const float dx = gx - b.x, dy = gy - b.y;
        const float reach = b.radius + 3.0f;
        if (dx * dx + dy * dy <= reach * reach) return i;
    }
    return -1;
}
```

### 3.3 与键盘 / 暂停共存

- 方向键与鼠标都写 `bodies[selectedBody].tx/ty`，按时间顺序自然覆盖（无需锁）。
- **暂停期间可拖动**：`WM_TIMER`(L1619) 现有结构为"无条件 `UpdateObstacleTarget` + 仅非暂停时 `AdvanceOneUiFrame`"。鼠标写入的目标会在恢复运行时被 `AdvanceObstacles` 追过去；如需暂停时即时预览，放开 `AdvanceObstacles` 对 `paused` 的限制即可（评估文档 §8 附加项 7）。
- 一次只拖一个物体（无并行拖动复杂度）。

### 3.4 验收

按住左键拖动物体 → 物体平滑跟随；松键停住；拖到 UI 面板上不响应；Jet 算例（无物体）左键拖拽无副作用；物体相互接近时不会重叠。

void SyncFlowScalarsToDevice(mrSolver2D& solver, int flowIndex) {

### 5.4 交互层级（关键稳定性设计）

- **流场交互 vs UI 交互隔离**：拖动物体 / 拾取（§3）只在 `!io.WantCaptureMouse` 且鼠标在 `layout.field` 内执行；ImGui 控件区（右侧面板）天然被 `WantCaptureMouse` 屏蔽，另加 `layout.panel` 矩形判断做双保险。
- **快捷键 vs 输入框**：`WM_KEYDOWN` 中若 `io.WantCaptureKeyboard`（如正在编辑数值输入框），跳过 `1/2/V/Space/R/+/-/Tab` 分支；方向键移动物体仅当 `!WantCaptureKeyboard`。
- **ImGui 窗口透明区**：控制窗口固定尺寸且不透明，其所在矩形整体视为"面板区"，防止拖动物体时鼠标滑入面板边缘造成抖动。
- 光标：进入 field 且 `!WantCaptureMouse` 时保持默认箭头即可（不做定制光标，减少不稳定因素）。

### 5.5 色条迁移

`DrawLegend`(L1336) 原画在右侧面板上，会与 ImGui 窗口重叠 → 改为 ImGui 内绘制：用 `ColorRamp` 生成 256×1 像素的 `GL_RGB` 纹理（复用 `CreateFieldTexture` 的同款纹理创建逻辑），在 PARAMETERS 分组下方用 `ImGui::Image` 显示；原 `DrawLegend` 与 `DrawPanel`(L1409-1551) **整体删除**（信息已全部迁入 ImGui）。
- ⚠️ **色条纹理的刷新时机**：Vorticity 模式用 `MapVorticityColor`（signed），Velocity 模式用 MAGMA（unsigned），两种模式内容不同。应在 `fieldView` 切换时（`ToggleFieldView`）或每帧按当前 `fieldView` 重建该 256×1 纹理；静态纹理会在切视图后残留旧色条。该纹理随 `ShutdownOpenGL` 一并 `glDeleteTextures`。

### 5.6 键盘保留项

`1/2`（算例切换）、`V`（视图）、`Space`（暂停）、`S`（单步）、`+/-`（步数）、`R`（重置）、`Esc`（退出）、方向键（移动选中物体）、新增 `Tab`（切换选中物体）。所有按键在 `WantCaptureKeyboard` 时让位给 ImGui。

## 6. 功能 6（附加模式）：手绘固体（画/擦，不可移动）

> 与"预制图形模式"（功能 1/2）**并列**的编辑模式；手绘形状为**静态固体 mask 层**：不可移动、不进 `AdvanceObstacles`、不算受力。难度评估见《扩展方案评估.md》§7。数据层与挂点已按 §1.4 预留，本节是完整实现要求。

### 6.1 模式与数据

```cpp
// LbmCases2D.h 新增（RigidBody 附近）
enum class EditMode { PresetObjects, FreehandSolid };

// LbmApp 新增字段（§1.4 已列）
EditMode editMode = EditMode::PresetObjects;
std::vector<uint8_t> drawnMask;   // 长度 = nx*ny；1 = 手绘固体格点
int  brushRadius = 6;             // 画笔/橡皮半径（格），UI 限 1~8
bool erasing = false;             // 本次按压是画(0)还是擦(1)
```

- `Init()`：`drawnMask.assign((size_t)nx * ny, 0); editMode = EditMode::PresetObjects; erasing = false;`
- 手绘 mask 不随 `ResetSimulation` 自动持久化（重建即清空，与"物体摆放"同策略）；如需保留，由 UI 提供显式按钮或并入 `params.ini`（本期不做，YAGNI）。

### 6.2 流固耦合合并（唯一核心改动）

1. `ApplyObstaclePoses`（§2.2）重分类判定由 `IsAnyObstacleCell(...)` 改为：

```cpp
const bool isSolid = drawnMask[idx] || IsAnyObstacleCell(bodies.data(),
                       bodyCount, obstacleShape, x, y);
```

2. `InitializeDemoCase`（§1.2 已改为数组签名）同步合并：新增参数 `const uint8_t* mask`（默认 `nullptr`），函数体内 `isSolid = (mask && mask[idx]) || IsAnyObstacleCell(...)`。

> 释放重建 / 新增写壁面矩 / touched / `SyncCellsToDevice` 全部原样复用。手绘格点"新增固体"走同一 `writeBoundaryMoments`（`wallUx = wallUy = 0`）。
> ⚠️ 由此，§2.2 第 2 步"owner 必然 >= 0"的假设在 FreehandSolid 模式下**不成立**：mask 格点新增固体时 `OwnerBodyOfCell` 返回 -1，必须按 §2.2 修正版取 `owner >= 0 ? wallUx[owner] : 0`，否则 `wallUx[-1]` 越界。

### 6.3 画笔与擦除（交互状态 + 执行函数）

**交互状态（合并进 `WindowProcedure`，复用 §1.3 消息）**

| 事件 | 动作 |
| --- | --- |
| 切换工具 | UI 工具单选设 `erasing`；右键按下（field 内）临时置 `erasing = true` |
| `WM_LBUTTONDOWN` | 若 `editMode == FreehandSolid` 且 `!WantCaptureMouse` 且在 field 内 → 记录笔刷圆心 = `(mouseFieldX, mouseFieldY)`，立即执行一次 |
| `WM_MOUSEMOVE` | 更新 `mouseFieldX/Y`；左键按住时持续执行 |
| `WM_LBUTTONUP` | 结束本次笔刷；右键抬起恢复 `erasing` 为工具值 |

**执行函数 `ApplyFreehandBrush()`（由 `ApplyMouseEffects()` 每帧调用，挂点见 §1.4）**

> ⚠️ **本节为审查修正版**：原稿有三处 API 与现有代码不符（会导致编译失败或"擦了没效果"）：① `AverageNeighborMoments` 实际签名是 7 参（`flow, x, y, oldFlags, newFlags, unchangedFluidOnly, result`），原稿只传 3 参；② `writeBoundaryMoments` 是 `ApplyObstaclePose` 内的局部 lambda，在 `ApplyFreehandBrush` 作用域不存在，且其第二参数应为"邻居索引"，传 `(idx, x, y, 0, 0)` 会把固体格点自己当邻居（读自己的矩）——画操作应直接用公开的 `WriteEquilibriumMoments2D(flow, idx, 1.0f, 0.0f, 0.0f)`（注释"平衡矩即可"与代码矛盾）；③ `SyncCellsToDevice` 实际签名是 `(solver, 0, indices, syncFlags)`，且画/擦都改了 `flow->flag`，必须 `syncFlags = true`，否则 GPU 端 flag 不更新（擦除无效）。修正版如下：

```cpp
void ApplyFreehandBrush() {
    const int nx = (int)flow->param->samples.x;
    const int ny = (int)flow->param->samples.y;
    const int count = nx * ny;
    std::vector<int> touched;
    // 与 ApplyObstaclePose 的"释放重建"同一机制：快照前后 flag 供 AverageNeighborMoments 用
    std::vector<MLLATTICENODE_FLAG> oldFlags(flow->flag, flow->flag + count);
    std::vector<MLLATTICENODE_FLAG> newFlags = oldFlags;
    const int cx = (int)mouseFieldX, cy = (int)mouseFieldY;
    for (int y = cy - brushRadius; y <= cy + brushRadius; y++)
        for (int x = cx - brushRadius; x <= cx + brushRadius; x++) {
            if (x < 1 || y < 1 || x >= nx - 1 || y >= ny - 1) continue; // 边界禁画
            const int idx = y * nx + x;
            // ⚠️ 笔刷形状固定用圆判据，勿复用全局 obstacleShape——
            //    否则全局形状切到 Box 时笔刷会变成方形（隐式耦合）
            const float dx = (float)x - mouseFieldX;
            const float dy = (float)y - mouseFieldY;
            if (dx * dx + dy * dy > (float)brushRadius * brushRadius) continue;
            if (erasing) {
                if (drawnMask[idx] && oldFlags[idx] == ML_SOLID
                    && OwnerBodyOfCell(bodies.data(), bodyCount, obstacleShape, x, y) == -1) {
                    drawnMask[idx] = 0;
                    newFlags[idx] = GetDemoCaseBaseFlag(*definition, x, y); // 恢复为流体（或边界 flag）
                    touched.push_back(idx);
                }
            } else {
                if (drawnMask[idx]) continue;                          // 已画过
                if (oldFlags[idx] != ML_FLUID) continue;               // 仅流体格可画
                if (IsAnyObstacleCell(bodies.data(), bodyCount, obstacleShape, x, y)) continue; // 物体优先
                drawnMask[idx] = 1;
                newFlags[idx] = ML_SOLID;
                WriteEquilibriumMoments2D(flow, idx, 1.0f, 0.0f, 0.0f); // 平衡矩即可（公开函数）
                touched.push_back(idx);
            }
        }
    // 擦除格点重建（与 ApplyObstaclePose 的 released 路径同机制）
    for (const int idx : touched) {
        if (!drawnMask[idx] && oldFlags[idx] == ML_SOLID) {           // 本次被擦除的
            const int x = idx % nx, y = idx / nx;
            Moments2D result;
            if (AverageNeighborMoments(flow, x, y, oldFlags, newFlags, true, result))
                WriteMoments2D(flow, idx, result.rho, result.ux, result.uy,
                               result.sxx, result.syy, result.sxy);
            else
                WriteEquilibriumMoments2D(flow, idx, 1.0f, 0.0f, 0.0f); // 无可用邻居兜底
        }
    }
    for (int idx = 0; idx < count; idx++) flow->flag[idx] = newFlags[idx];
    // ⚠️ 画/擦都改了 flag → 必须 syncFlags = true；否则设备端 flag 不更新
    SyncCellsToDevice(solver, 0, touched, /*syncFlags=*/true);
}
```

> 数值稳定性要点：**新画固体必须写合法矩**（平衡矩 `rho=1, u=0` 已足够），禁止只改 `flag`，否则 GPU pull streaming 读到垃圾矩 → 流场发散。擦除走 `AverageNeighborMoments`（与移动物体"释放重建"同一机制，[testMrLBM2D.cpp L326-393](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L326-393)）。

### 6.4 受力配合

`ComputeSolidLoads`（§2.4）对每个固体邻居反查 `owner` 后，`owner == -1`（手绘格点）**跳过累加**——手绘固体不算入任何物体受力。

### 6.5 绘制与 UI

- **绘制**：手绘固体无需额外轮廓（`BuildFieldImage` 已把 `ML_SOLID` 涂成固体色）。可选：在 `DrawBodies` 之后画一层半透明笔刷圆环（光标指示），仅当 `editMode == FreehandSolid` 时显示。
- **UI（§5.3 EDIT MODE 分组填充）**：

| 控件 | 说明 |
| --- | --- |
| 编辑模式下拉 | PresetObjects / FreehandSolid；切换即调一次 `ApplyObstaclePoses`（当前姿态）完成重分类 |
| 工具单选 | Paint / Erase（写 `erasing`） |
| 笔刷半径滑块 | 1 ~ 8 |
| `[Clear all freehand]` | `drawnMask` 全清零 + 一次 `ApplyObstaclePoses`（复用释放重建路径） |

### 6.6 与物体系统的重叠规则

- 优先级：**物体 > 手绘**。笔刷命中物体格点时画操作跳过（`IsAnyObstacleCell` 拦截），`OwnerBodyOfCell` 无歧义。
- 切回 PresetObjects 模式后手绘 mask **保留**（`drawnMask` 不清），随时可切回继续编辑或清空。

### 6.7 验收

切到手绘模式，左键画任意形状 → 流场绕流且长时间运行稳定；橡皮擦除 → 恢复流体；与预制物体并存时不冲突；Jet 算例（无物体）同样可手绘；`[Clear all freehand]` 一次清空。

## 7. 稳定性要求（贯穿性检查清单）

1. **`definition` 值化顺序**：`Init()` 内先赋值 `definition = GetDefaultDefinition(...)` 再读它的字段；`Release()` 不再碰 `definition`。全文件替换 `definition->` 后编译一次确认无遗漏。
2. **`bodies` 生命周期**：每次 `Init()` 先 `bodies.fill({})` 再写 `bodies[0]`，杜绝残留脏数据；`bodyCount` 恒 ≤ `kMaxBodies`，所有数组索引处防越界。
3. **重分类幂等**：`ApplyObstaclePoses` 全量重分类在 96×192 上开销极小（每帧仅拖动时调用）；形状切换、增删物体都复用同一入口，不另造路径。
4. **鼠标映射互逆**：`ScreenToFieldPoint` 分母与 `DrawBodies` 一致（`nx-1 / ny-1`）；拖动的 `tx/ty` 必须 clamp 在 `[margin, nx-margin-1]`（margin = radius+2），防止物体滑出边界。
5. **ImGui 时序**：`NewFrame` 每帧恰好一次（只放 `Render()`）；窗口 `width/height <= 0` 直接返回；消息转发"先自身状态、后 handler、再按 WantCapture 分支"，严禁入口统一 `return`。
6. **流场/UI 冲突**：拖动物体双保险（`WantCaptureMouse` + `panel` 矩形）；`WM_KILLFOCUS` 与 `WM_LBUTTONUP` 都要复位 `dragging`。
7. **热更新边界**：严格按 §4.1 三分类分发；粘度同步前先写 `host->vis_shear`；`jetWidth / nx / ny / initialUx / initialUy` 一律重建，不图省事。
8. **参数文件**：`LoadAppParams` 以默认 `def` 为基底覆盖、非法值回退，启动加载失败不阻塞；保存用临时文件 + `rename` 或直接覆盖均可（单进程独占）。
9. **ImGui 与 OpenGL 状态**：后端自管矩阵/混合状态，现有立即模式代码无需改动；勿在 `glBegin/glEnd` 之间调用任何 ImGui 函数。
10. **编译面**：`.cu` 不 include ImGui；保持 `Release|x64` 配置；vcxproj 增删文件后整编一次确认。
11. **手绘矩合法性**：新画固体必须写合法矩（平衡矩即可，§6.3），**禁止只改 flag**，否则 pull streaming 读到垃圾矩 → 发散。
12. **手绘边界与归属**：mask 只允许落在内部 `ML_FLUID` 格点；与物体重叠时"物体优先"（画操作跳过）；`ComputeSolidLoads` 对 `owner == -1` 的手绘格点跳过累加。
13. **画笔/擦除同步（§6.3 修正版）**：画/擦都修改 `flow->flag`，`SyncCellsToDevice` 必须 `syncFlags = true`；擦除重建用 `AverageNeighborMoments` 完整 7 参签名；画操作用 `WriteEquilibriumMoments2D`，禁止用 `ApplyObstaclePose` 内局部 lambda。
14. **拖动捕获（§3.1）**：`WM_LBUTTONDOWN` 命中后 `SetCapture(window)`，`WM_LBUTTONUP / WM_KILLFOCUS` 释放并复位 `dragging`；拖动更新前查 `io.WantCaptureMouse`。
15. **物体数据一致性（§2.5 / §4.1）**：删除物体后修复 `selectedBody` 与 `selected` 标志；UI 改 `bodies[0]` 半径/中心时同步 `definition.obstacle*`（Re 显示）；`bodyCount == 0` 时所有数组索引防越界。
16. **参数文件二次校验（§4.3）**：`LoadAppParams` 内完成坐标 clamp / 半径上限 / 两两不重叠 / `bodyCount` 截断，非法值回退默认；与 `--case` 的优先级显式定义。
17. **smoke 设备指针（§1.4）**：设备端分配与释放必须配套（方案 A），或显式置 NULL 且不释放（方案 B），禁止对 host 指针 `cudaFree`。

### 11.4 本次审查结论

- 原稿整体架构（参数值化 → bodies 数组 → 单一动流固耦合口 `ApplyObstaclePoses` → ImGui UI）成立，**无需推倒重来**。
- 风险最集中的是 §6.3（三个 API 不匹配）与 §1.4（设备端指针陷阱），二者已按"修正版"重写；§2.2/§2.4/§4.1 的"owner == -1 / 门控矛盾 / Re 数据同源"属于**手绘与多物体两个子系统合并后才暴露**的交叉问题，务必在 M2（多物体）与 M7（手绘）落地前对好接口。
- 新增 17 条稳定性条目（§7 第 13~17 条）与本节对照表，作为实施与 code review 的核对清单。
