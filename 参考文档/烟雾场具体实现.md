## 1. 需求解读与总体设计

### 1.1 三个需求的语义分析

**需求 1（烟雾视图）**：现有视图要么显示速度（Velocity）、要么显示涡量（Vorticity）、要么显示"流动状态"（Colorful），都包含常规流体信息。烟雾视图要求**只显示烟雾状态**：每个格点显示该处烟雾的颜色，障碍物仍以深色标出（"全场除了障碍物"暗示障碍物是例外）。因此渲染就是"取烟场颜色"，与速度/涡量完全无关。

**需求 2（烟雾工具 + 默认白烟）**：关键句是"烟雾默认全是白烟（即全场除了障碍物全都是白色状态）"。它描述的**不是**调色板的默认值，而是**烟场的初始状态**——整个流场区域被白色烟雾填满（浓度满、颜色白）。调色板用于选择"要生成的烟雾"的颜色；选中工具后左键在目标点**生成一片（该颜色的）烟雾云**。生成后烟雾云被风吹动、扩散、混合——这正是"扩散烟雾"的含义。

**需求 3（被动标量）**：烟不反作用流体（不参与动量/密度），只读取速度场被搬运。GPU 的 LBM 求解器完全不感知烟的存在。

### 1.2 核心模型：彩色颜料场（RGB 三通道被动标量）

**结论先行**：烟场用 **每个格点一个 RGB 颜色（3 个独立被动标量）** 表示，初始化为白色 `(1,1,1)`；工具注入调色板颜色；每帧对三个通道分别做半拉格朗日平流；烟雾视图直接渲染该颜色。理由：

1. **调色板 ⇒ 必须支持多颜色**。单浓度标量 + 全局显示色无法表达"不同位置不同颜色的烟"，调色板将失去意义。
2. **RGB 三通道本身就是被动标量**。每个通道独立满足"被风吹动的颜料"语义，物理上就是 Stam 式"dye advection"，实现代价只是 3 倍的单标量平流。
3. **白色初始态与颜料模型天然自洽**。均匀白色场平流后仍是均匀白色（背景稳定）；注入的彩色烟被搬运时与白色背景混合（双线性插值天然产生渐变），视觉上正是"烟在空气中扩散"。
4. **不需要 alpha/浓度通道**。白色即"满"状态，也是唯一背景，无需透明度合成；浓度语义由颜色亮度隐含携带。

**为什么不用 `ML_SMOKE` flag**（[mlLbmCommon.h L24](file:///d:/Code/CG/Phy/home2d/common/mlLbmCommon.h#L24)）：flag 是格点类型枚举（FLUID/SOLID/INLET…），烟是连续标量（颜色），二者语义不同；用 flag 无法表达浓度/颜色，还会污染边界分类逻辑（kernel 按 flag 判断流体格点）。烟数据一律放独立数组。

**备选方案对比**（供评审）：

| 方案 | 描述 | 结论 |
| --- | --- | --- |
| A. RGB 颜色场（本方案） | 每格 3 个 float，各通道独立平流 | 满足全部需求，实现最简，**采用** |
| B. 单浓度 + 全局颜色 | 每格 1 个浓度，显示色固定 | 调色板无法产生多色烟，**不采用** |
| C. 多"烟种"浓度场（N 个染料） | 每种颜色一个标量场，显示 = 加权混合 | RGB 已覆盖需求且更简单，**过度设计** |
| D. RGBA 颜色场 | 多一个 alpha 通道 | 白色背景已承担"底"，alpha 冗余，**不采用** |

### 1.3 存储位置：`LbmApp` 成员（host-only），不改 `mrFlow2D`

烟场存为 `LbmApp` 的 `std::vector<REAL>` 成员，**不**加进 `mrFlow2D`。原因：

1. **零 CUDA 指针风险**：烟不进 `mlTransData2Gpu`/`mlDeepCopy`/`SyncCellsToDevice`/`CopyMomentsFromDevice` 任何同步路径。若加进 `mrFlow2D`，必须处理"host 堆指针被整结构拷进设备结构体"的陷阱（既有文档 §1.4 已论证：方案 A 需配套分配/释放、方案 B 需显式置 NULL），属于无谓的改动面。
2. **烟是纯显示/交互层数据**：显示只需要每帧已就位的 host 速度；烟不参与任何求解。
3. **改动面最小**：`mrFlow2D.h`、`mrSolver2D.h`、`ReleaseDeviceData`、所有同步函数全部不动，`.cu` 内核零改动（kernel 只读 `fMom/flag/forcex/forcey/vis_shear`，[mrLbmSolverGpu2D.cu](file:///d:/Code/CG/Phy/home2d/inc/2D/gpu/mrLbmSolverGpu2D.cu#L28-L77)）。
4. 内存量：96×192×3×4 B ≈ **221 KB**，可忽略。

### 1.4 每帧执行序列（`Step()` 改造后）

现有 `Step()`（[testMrLBM2D.cpp L1495-L1520](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L1495-L1520)）改造为：

```
ApplyMouseEffects()             // ① 左键 + PaintSmoke → 向 smoke[] 注入调色板颜色（纯 host）
RefreshDemoCaseBoundaries()     // ② host 边界矩
SyncOuterBoundaryMomentsToDevice()
for step in stepsPerFrame: mlIterateGpu()   // ③ LBM 推进（含 MomSwap）

```

**顺序依据**：
- 注入（①）在平流（⑤）之前：本帧画的烟**本帧**就被最新速度带走，视觉跟手。
- 平流（⑤）在 `CopyMomentsFromDevice`（④）之后：必须用最新速度，否则烟滞后一帧。
- 平流在 LBM 循环之后：一 UI 帧推进 `stepsPerFrame` 个 LBM 步，烟平流应覆盖整帧时间（`dt = stepsPerFrame`，见 §3.2）。

`smoke` 与 `smokeScratch` 都是 `std::vector<REAL>`，平流每子步**读 `smoke`（旧）写 `smokeScratch`（新）**，子步结束后 `std::copy(smokeScratch.begin(), smokeScratch.end(), smoke.begin())` 回拷，保证下一子步与最终结果始终在 `smoke`。**禁止** `std::swap(smoke.data(), scratch.data())` 这类指针交换（vector 内部缓冲与语义混乱，无必要）。

## 3. 被动标量平流 `AdvectSmoke()`

### 3.1 数学原理

半拉格朗日回溯：**目标格点的新颜色 = 沿速度场回溯 `dt` 时间后位置的旧颜色**（每通道独立）：

```
C_new(x, y) = C_old(xb, yb)
xb = x - ux(x, y) * dt
yb = y - uy(x, y) * dt
```

- 无条件稳定（无 CFL 限制），一阶精度——对可视化烟迹完全足够。
- 速度 `ux/uy` 取 `flow->fMom[idx*6+1] / flow->fMom[idx*6+2]`（每帧已由 `CopyMomentsFromDevice` 回 host）。

### 3.2 `dt` 的选取

`Step()` 每 UI 帧推进 `stepsPerFrame` 个 LBM 步（格点单位，`delta_t = delta_x = 1`），烟平流应覆盖整帧时间：

- **`dt = (REAL)stepsPerFrame`**，每帧一次平流。
- **子步拆分**：`substeps = max(1, ceil(dt / 0.75f))`，每子步 `dtStep = dt / substeps`，回溯距离 ≤ 0.75 格，双线性插值不糊。典型默认 `stepsPerFrame = 15` → 15 子步；上限 50 → 67 子步。18k 格 × 3 通道 × 67 ≈ 370 万次采样/帧，CPU 毫秒级。
- 同一速度快照内迭代子步（速度每帧只更新一次，这是与 LBM 求解的一致性取舍，见 §3.9）。

### 3.3 双线性插值与越界 clamp

```
i0 = floor(xb); j0 = floor(yb); fx = xb - i0; fy = yb - j0
(i0, j0) 各自 clamp 到 [0, nx-1] / [0, ny-1]（与 GPU kernel 同风格，mrLbmSolverGpu2D.cu L38-L44）
i1 = min(i0+1, nx-1); j1 = min(j0+1, ny-1)
每个通道 c：
  top  = (1-fx)*S[j0][i0][c] + fx*S[j0][i1][c]
  bot  = (1-fx)*S[j1][i0][c] + fx*S[j1][i1][c]
  C_new[c] = (1-fy)*top + fy*bot
```

### 3.4 三类格点的处理规则

| 格点类型 | 规则 | 理由 |
| --- | --- | --- |
| `ML_FLUID` | 正常半拉格朗日平流 | 核心格点 |
| `ML_SOLID` | **保持自身旧值**，不参与平流、不采样外部 | 烟不得穿壁；物体内部不需要烟（也不显示）；释放格点因此天然为白，不会"瞬移"出彩色烟 |
| `ML_INLET / ML_OUTLET / ML_WALL_*` | **强制置白 (1,1,1)** | 入口来流洁净（新白烟随流上行）；出口烟离开即融入白底、不堆积；壁面无烟 |

> 用 `flag != ML_FLUID && flag != ML_SOLID` 判定边界，天然覆盖全部非流体/非固体枚举（含未来新增边界类型）。注意：`ML_FLUID_REST`（3D 遗留枚举，2D 算例不使用）也会被归入"边界→置白"。这与现有代码约定一致——kernel 与 `ApplyToolAt` 都只认 `== ML_FLUID`（[mrLbmSolverGpu2D.cu L28](file:///d:/Code/CG/Phy/home2d/inc/2D/gpu/mrLbmSolverGpu2D.cu#L28)、[testMrLBM2D.cpp L1383](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L1383)），GetDemoCaseBaseFlag 也只产生 FLUID/SOLID/INLET/OUTLET/WALL_*，故无实际影响；如追求严谨可把条件写成 `flag != ML_FLUID && flag != ML_FLUID_REST && flag != ML_SOLID`。

**回溯采样遇固体的回退**：回溯点所在四邻域含 `ML_SOLID` 时，本格点取自身旧值（不采样）。烟在物体表面"贴边滞留"而不会穿透，视觉正确。

### 3.5 速度场可用性论证

平流只对 `ML_FLUID` 格点执行，回溯用**本格点**速度（流体格点必有合法速度）。采样到的旧颜色可能落在：
- 边界格点 → 已被强制置白 → 采到白（烟流出即消失），正确；
- 固体格点 → §3.4 回退规则接管（取自身旧值），不会把体内值带入流场。

### 3.6 数值守卫

对每个格点先检查 `IsFinite(ux) && IsFinite(uy) && ux²+uy² ≤ 1.0`（复用现有 [IsFinite](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L92-L95)）；不满足则保持旧值。开销 18k 次/帧可忽略，防止 NaN 污染整片烟场。

### 3.7 伪代码

```cpp
void LbmApp::AdvectSmoke() {
    const int nx = definition.nx, ny = definition.ny;
    const int cells = nx * ny;
    if ((int)smoke.size() != cells * 3) return;          // Init 未完成，防御
    smokeScratch.resize((size_t)cells * 3);

    const REAL dt = (REAL)stepsPerFrame;
    const int substeps = std::max(1, (int)std::ceil(dt / 0.75f));
    const REAL dtStep = dt / (REAL)substeps;

    for (int s = 0; s < substeps; s++) {
        for (int y = 0; y < ny; y++) {
            for (int x = 0; x < nx; x++) {
                const int idx = y * nx + x;
                const MLLATTICENODE_FLAG flag = flow->flag[idx];

                // 边界强制置白（含 INLET/OUTLET/WALL_*）
                if (flag != ML_FLUID && flag != ML_SOLID) {
                    smokeScratch[idx*3+0] = smokeScratch[idx*3+1] = smokeScratch[idx*3+2] = 1.0f;
                    continue;
                }
                // 固体保持自身旧值
                if (flag == ML_SOLID) {
                    smokeScratch[idx*3+0] = smoke[idx*3+0];
                    smokeScratch[idx*3+1] = smoke[idx*3+1];
                    smokeScratch[idx*3+2] = smoke[idx*3+2];
                    continue;
                }

                const REAL ux = flow->fMom[idx*6+1];
                const REAL uy = flow->fMom[idx*6+2];
                if (!IsFinite(ux) || !IsFinite(uy) || ux*ux + uy*uy > 1.0f) {
                    smokeScratch[idx*3+0] = smoke[idx*3+0];
                    smokeScratch[idx*3+1] = smoke[idx*3+1];
                    smokeScratch[idx*3+2] = smoke[idx*3+2];
                    continue;   // 数值守卫
                }

                const REAL xb = (REAL)x - ux * dtStep;
                const REAL yb = (REAL)y - uy * dtStep;
                int i0 = (int)std::floor(xb); int j0 = (int)std::floor(yb);
                if (i0 < 0) i0 = 0; if (i0 >= nx) i0 = nx - 1;
                if (j0 < 0) j0 = 0; if (j0 >= ny) j0 = ny - 1;
                const int i1 = std::min(i0 + 1, nx - 1);
                const int j1 = std::min(j0 + 1, ny - 1);

                // 采样邻域含固体 → 回退取自身旧值
                if (flow->flag[j0*nx+i0] == ML_SOLID ||
                    flow->flag[j0*nx+i1] == ML_SOLID ||
                    flow->flag[j1*nx+i0] == ML_SOLID ||
                    flow->flag[j1*nx+i1] == ML_SOLID) {
                    smokeScratch[idx*3+0] = smoke[idx*3+0];
                    smokeScratch[idx*3+1] = smoke[idx*3+1];
                    smokeScratch[idx*3+2] = smoke[idx*3+2];
                    continue;
                }

                const float fx = (float)(xb - (REAL)i0);
                const float fy = (float)(yb - (REAL)j0);
                for (int c = 0; c < 3; c++) {
                    const REAL s00 = smoke[(j0*nx+i0)*3+c];
                    const REAL s10 = smoke[(j0*nx+i1)*3+c];
                    const REAL s01 = smoke[(j1*nx+i0)*3+c];
                    const REAL s11 = smoke[(j1*nx+i1)*3+c];
                    const REAL top = (1.0f-fx)*s00 + fx*s10;
                    const REAL bot = (1.0f-fx)*s01 + fx*s11;
                    smokeScratch[idx*3+c] = ClampFloat((1.0f-fy)*top + fy*bot, 0.0f, 1.0f);
                }
            }
        }
        // 子步回拷：smoke 始终是"当前最新"，下一子步继续读它 → 子步间自然级联
        std::copy(smokeScratch.begin(), smokeScratch.end(), smoke.begin());
    }

    // 可选：向白轻微松弛，模拟烟随时间的消散/混合（smokeFade=0 则纯平流）
    if (smokeFade > 0.0f) {
        for (int i = 0; i < cells * 3; i++) {
            smoke[i] = ClampFloat(smoke[i] + smokeFade * (1.0f - smoke[i]), 0.0f, 1.0f);
        }
    }
}
```

> 双线性插值是凸组合，`ClampFloat(…, 0, 1)` 是保险性钳制（浮点舍入），颜色永不越界。

### 3.8 可选：消散参数 `smokeFade`

- `smokeFade = 0`（默认）：纯"颜料"语义，彩色烟只搬运不消失。
- `smokeFade > 0`（如 0.002）：彩色烟缓慢向白褪去，模拟烟散开稀释；数值上等价于颜色向背景色松弛。
- 不属于需求硬性要求，作为可调滑块提供（YAGNI 权衡：一行代码，演示效果好）。

### 3.9 精度取舍（显式说明）

速度每 UI 帧只取**帧末**快照（LBM 循环之后 `CopyMomentsFromDevice`），烟平流用该快照覆盖整帧 `dt = stepsPerFrame`。这是一阶近似：烟"看到"的是本帧结束时的速度场。对可视化烟迹足够；若要求更严格，可在每次 `mlIterateGpu()` 之后多拷一次速度并平流（代价是 N 次 D2H 拷贝），本期不做（YAGNI）。此取舍不影响稳定性（半拉格朗日无条件稳定）。

```cpp
case InteractionTool::PaintSmoke:
{
    // "生成一片烟雾"：中心最强、边缘渐弱；rate 越高越接近纯调色板色
    const float dist = sqrtf(dx*dx + dy*dy);
    const float falloff = std::max(0.0f, 1.0f - dist / brushRadius);
    const float amount = ClampFloat(falloff * smokeRate, 0.0f, 1.0f);
    for (int c = 0; c < 3; c++) {
        smoke[idx*3+c] = ClampFloat(
            smoke[idx*3+c] + amount * (smokeColor[c] - smoke[idx*3+c]), 0.0f, 1.0f);

}
```

## 8. 稳定性与健壮性清单

1. **纯 host 数据，零同步**：`smoke/smokeScratch` 不进任何 D2H/H2D 拷贝与 `SyncCellsToDevice`；kernel 不读烟 → `.cu` 零改动，流场求解与现状完全一致。
2. **颜色 clamp**：注入与插值结果一律 clamp 到 `[0,1]`（凸组合 + 保险钳制）。
3. **边界置白**：INLET/OUTLET/WALL_* 每子步强制白，入口洁净、出口不堆积、壁面无烟。
4. **固体不透烟**：固体格点不参与平流、采样遇固体回退自身旧值 → 烟不穿壁。**默认（静止障碍物）下释放格点天然为白**（固体自 Init 起就是白且从不接收烟色）；**已知边界行为**：若移动物体压过彩色烟区域再移开，被覆盖格点冻结了被压前的旧色（"保持旧值"语义），释放后会短暂重现旧色烟——可接受（视觉上类似"被遮挡的烟重见天日"）；若希望彻底清除，把 `ML_SOLID` 分支改为强制置白即可（但那样烟会在物体移开后消失，两害相权文档默认"保持旧值"）。
5. **平流数值守卫**：速度非有限或 `|u|>1` 跳过该格点，防 NaN 蔓延（速度上限 `umax2d_gpu = 0.3` 已从源头限制）。
6. **双缓冲纪律**：每子步 `std::copy` 回拷；`smoke` 始终是"当前最新"；禁止指针 swap。
7. **子步拆分**：回溯 ≤ 0.75 格/子步，大 `stepsPerFrame` 下不糊。
8. **被动性**：烟不反作用流场；Blow/Vortex 力源对烟的效果**是**对速度场的效果（间接驱动烟），符合需求 3。
9. **生命周期**：`Init` 填白、`Release` 清空，重建算例后烟场无残留；视图切换不破坏烟场。所有重建路径（Reset / Restart / 启动 / Load ini）都经过 `LbmApp::Init`（[L3084](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L3084)、[L3130](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L3130)、[L3340](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L3340)），烟场复位全覆盖。
10. **渲染空指针保护**：`BuildFieldImage` 的第 5 参 `smokeRgb` 带默认 `nullptr`，Smoke 分支做 NULL 判断退化为白色——未初始化/异常路径不会读脏指针（§5.2）。
11. **回归**：不选 Smoke 工具、不切 Smoke 视图时，原行为与实现前完全一致（烟场存在但不可见，开销仅 2×221KB 内存 + 每帧毫秒级 CPU 平流）。

## 10. 验收清单

1. **烟雾视图**：切到 Smoke 视图后，全场白色、障碍物深色；不显示速度/涡量/密度任何信息；速度视图下无烟色。
2. **默认白烟**：新建算例（`R` 重置 / `1`/`2` 切 Case / 重启）后烟场立即为全白，无需任何操作。
3. **烟雾工具**：选中 Smoke 工具（自动切到 Smoke 视图），调色板改色后左键在目标点生成一片该颜色的烟云，松开后烟云仍存在。
4. **被动平流**：生成的烟云被主流场带走（Karman 上移、Jet 喷流裹挟），沿速度方向形成烟带；吹风（Shift+左键）/旋涡（中键）搅动后烟迹随流弯折。
5. **边界行为**：烟到达出口消失（融入白底），入口始终洁净白色，壁面不积累烟；固体/障碍物表面烟不穿透。
6. **数值稳定**：反复涂抹 + 吹风 + 旋涡 5 分钟无 NaN、无颜色越界、无崩溃。
7. **回归**：不使用烟雾功能时，原 Karman/Jet 的显示、交互、受力行为与实现前完全一致。
