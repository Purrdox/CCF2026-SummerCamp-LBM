## 1. 总体设计

### 1.1 为什么"host-only"（三个原因，均来自现有代码结构）

1. **显示需求只需要速度场**：烟平流只需格点速度 `(ux, uy)`，即 `fMom[idx*6+1/2]`。该数据每帧已由 `CopyMomentsFromDevice` 拷回 host（[testMrLBM2D.cpp L141-L165](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L141-L165)），CPU 平流零额外同步成本。
2. **GPU 内核不读 smoke**：`mrSolver2DKernel` 只读 `fMom / flag / forcex / forcey / vis_shear`（[mrLbmSolverGpu2D.cu](file:///d:/Code/CG/Phy/home2d/inc/2D/gpu/mrLbmSolverGpu2D.cu#L28-L77)），烟场不影响流动。设备端分配 smoke 纯属浪费显存与 deep-copy 复杂度。
3. **设备指针陷阱**：`mlTransData2Gpu` 用 `sizeof(mrFlow2D)` 整结构拷贝，若设备端不显式把 `smoke` 置 NULL，host 堆指针会被拷进设备结构体，后续任何对 `deviceCopy.smoke` 的 `cudaFree` 都会崩溃（方案 B 已规避，[mrSolver2D.h](file:///d:/Code/CG/Phy/home2d/inc/2D/cpu/mrSolver2D.h#L175-L181)）。

### 1.2 每帧执行序列（`Step()` 改造后）

现有 `Step()`（[testMrLBM2D.cpp L1236-L1260](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L1236-L1260)）顺序为：

改造后插入两步（均纯 host，改动集中在 `Step` 与两个新函数）：


**顺序依据**：
- 烟注入（①）在平流（④）之前：本帧画的烟本帧就被速度场带走，视觉跟手。
- 力（②）在 LBM 循环之前：与现有 kernel 的体力半时间步格式匹配（`ux = (ux·ρ + 0.5·Fx)/ρ`，[mrLbmSolverGpu2D.cu L69-L72](file:///d:/Code/CG/Phy/home2d/inc/2D/gpu/mrLbmSolverGpu2D.cu#L69-L72)）。
- 平流（④）在 `CopyMomentsFromDevice` 之后：必须用**最新**速度场，否则烟滞后一帧。
- 清力（③）在 LBM 循环之后：保证注入的力"只活一帧"（§5.3 详述）。

## 3. 半拉格朗日平流 `AdvectSmoke()`

### 3.1 数学原理

半拉格朗日回溯：**目标格点的新浓度 = 沿速度场回溯 `dt` 时间后位置的旧浓度**：

```
S_new(x, y) = S_old(xb, yb)
xb = x - ux(x, y) · dt
yb = y - uy(x, y) · dt
```

- 无条件稳定（无 CFL 限制），单步精度一阶——对可视化烟迹完全足够。
- 速度 `ux/uy` 取自 `fMom[idx*6+1] / [idx*6+2]`（每帧已回 host）。

### 3.2 `dt` 的选取（与 `stepsPerFrame` 的关系）

`Step()` 每 UI 帧推进 `stepsPerFrame` 个 LBM 步，速度场是"每 LBM 步"的格点速度（格点单位，`delta_t = delta_x = 1`，[mrFlow2D.h L89](file:///d:/Code/CG/Phy/home2d/inc/2D/cpu/mrFlow2D.h#L89)）。平流应覆盖整帧时间：

- **基准方案**：`dt = (REAL)stepsPerFrame`，每帧一次平流。典型参数（Karman 入口 `uy = 0.10`，默认 `stepsPerFrame = 15`）回溯距离 `|u|·dt ≈ 1.5` 格——小于 2 格，插值误差可接受。
- **大步数安全阀**：`stepsPerFrame` 上限 50（[testMrLBM2D.cpp L40](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L40)），此时回溯距离可达 5 格，单步插值会变糊。处理方式（二选一，推荐 A）：
  - **A. 子步拆分（推荐）**：`n = ceil(dt / 1.0)`，循环 `n` 次、每次 `dt_step = dt / n`（≤1 格/步），同一速度快照内多次迭代。18k 格 × ≤50 次 ≈ 90 万次采样/帧，CPU 毫秒级，可忽略。
  - B. 单步但截断回溯距离 ≤ 2 格：省算力但大 `stepsPerFrame` 下烟迹偏慢。
- 两种都无条件稳定；文档按**子步拆分**给出伪码。

### 3.3 双线性插值与越界 clamp

回溯点 `(xb, yb)` 一般不是整数格点，用四邻域双线性插值：

```
i0 = floor(xb); j0 = floor(yb); fx = xb - i0; fy = yb - j0
(i0, j0) 各自 clamp 到 [0, nx-1] / [0, ny-1]（与 GPU kernel 同款 clamp 风格，
   见 mrLbmSolverGpu2D.cu L38-L44）
i1 = min(i0+1, nx-1); j1 = min(j0+1, ny-1)
S00 = S_old[j0*nx+i0]; S10 = S_old[j0*nx+i1]
S01 = S_old[j1*nx+i0]; S11 = S_old[j1*nx+i1]
S_new = (1-fy)*((1-fx)*S00 + fx*S10) + fy*((1-fx)*S01 + fx*S11)
```

### 3.4 三类格点的处理规则

| 格点类型 | 规则 | 理由 |
| --- | --- | --- |
| `ML_FLUID` | 正常半拉格朗日平流 | 核心格点 |
| `ML_SOLID` | **保持自身旧值**，不参与平流、不采样外部 | 体内烟（物体冒烟注入到**固体邻居流体格点**，见 §4，体内不需要烟）；避免把体内值插进流场造成"烟透壁" |
| `ML_INLET / ML_OUTLET / ML_WALL_*` | 平流后**强制置 0** | 入口来流洁净；出口消散防堆积（评估文档 §9 附加 12）；壁面无烟（§7 详述） |

> 注：伪码实现用 `flag != ML_FLUID && flag != ML_SOLID` 判边界——**天然覆盖全部非流体/非固体枚举**。已核实现有算例只用到 `ML_INLET / ML_OUTLET / ML_WALL_DOWN / ML_WALL_LEFT / ML_WALL_RIGHT`（[LbmCases2D.cpp L193-L217](file:///d:/Code/CG/Phy/home2d/src/LbmCases2D.cpp#L193-L217)），`ML_FLUID_REST / ML_EMPTY / ML_INLET0-2 / ML_WALL_UP / ML_WALL_FOR / ML_WALL_BACK / ML_WALL_CORNER` 均未使用；未来新增边界类型时此分支也自动清零，无需改动。

**回溯采样遇固体的回退**（对应评估文档 §1.4"固壁/固体格点采样回退到最近流体"）：当回溯点所在的四邻域含 `ML_SOLID` 时，本格点**取自身旧值**（不采样）。这样烟在物体表面会"贴边滞留"而不会穿透，视觉上正是物体冒烟的尾迹效果。此规则为可视化简化，稳定且实现最简；若要更精细可在采样时只对流体角加权（本期不做，YAGNI）。

### 3.5 速度场可用性论证（为什么回溯不需要额外处理）

平流只对 `ML_FLUID` 格点执行，回溯用的速度是**本格点**的速度：
- 流体格点：正常宏观速度；
- 因此不会出现"用固体格点速度回溯"的情形。

而**采样**的旧浓度可能落在任意类型格点：
- 落在边界格点 → 该格点浓度已被强制置 0（§3.4），采样得 0，正确（烟流出即消失）；
- 落在固体格点 → §3.4 回退规则接管（取自身旧值），不会采样到体内值。

### 3.6 数值守卫

`CopyMomentsFromDevice` 拷回的 `fMom` 理论上可能含非有限值（数值发散前的瞬间）。平流对每个格点先做一次有限性检查（复用现有 `IsFinite`，[testMrLBM2D.cpp L82-L85](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L82-L85)）：`ux/uy` 非有限或 `|u| > 1.0` 时跳过该格点平流（保持旧值）。开销 18k 次 `isfinite`/帧，可忽略，但能防止 NaN 污染整片烟场。

### 3.7 伪代码

```cpp
void LbmApp::AdvectSmoke() {
    const int nx = definition.nx, ny = definition.ny;
    if ((int)smokeScratch.size() != nx * ny) smokeScratch.resize((size_t)nx * ny);
    const REAL dt = (REAL)stepsPerFrame;
    const int substeps = std::max(1, (int)std::ceil(dt));   // 子步：每步 ≤ 1 格
    const REAL dtStep = dt / (REAL)substeps;

    // 子步循环：旧值 -> smokeScratch -> 交换，使子步间自然级联
    for (int s = 0; s < substeps; s++) {
        for (int y = 0; y < ny; y++) {
            for (int x = 0; x < nx; x++) {
                const int idx = y * nx + x;
                const MLLATTICENODE_FLAG flag = flow->flag[idx];

                // 边界强制清零（含角点；INLET/OUTLET/WALL_* 全置 0）
                if (flag != ML_FLUID && flag != ML_SOLID) {
                    smokeScratch[idx] = 0.0f;
                    continue;
                }
                if (flag == ML_SOLID) {          // 固体保持自身旧值
                    smokeScratch[idx] = smoke[idx];
                    continue;
                }

                const REAL ux = flow->fMom[idx * 6 + 1];
                const REAL uy = flow->fMom[idx * 6 + 2];
                if (!IsFinite(ux) || !IsFinite(uy) || ux * ux + uy * uy > 1.0f) {
                    smokeScratch[idx] = smoke[idx];   // 数值守卫
                    continue;
                }

                const REAL xb = (REAL)x - ux * dtStep;
                const REAL yb = (REAL)y - uy * dtStep;
                // 回溯点越界 clamp（与 kernel 同风格）
                int i0 = (int)std::floor(xb); int j0 = (int)std::floor(yb);
                if (i0 < 0) i0 = 0; if (i0 >= nx) i0 = nx - 1;
                if (j0 < 0) j0 = 0; if (j0 >= ny) j0 = ny - 1;
                const int i1 = std::min(i0 + 1, nx - 1);
                const int j1 = std::min(j0 + 1, ny - 1);

                // 采样邻域含固体 → 回退取自身旧值
                if (flow->flag[j0 * nx + i0] == ML_SOLID ||
                    flow->flag[j0 * nx + i1] == ML_SOLID ||
                    flow->flag[j1 * nx + i0] == ML_SOLID ||
                    flow->flag[j1 * nx + i1] == ML_SOLID) {
                    smokeScratch[idx] = smoke[idx];
                    continue;
                }

                const float fx = (float)(xb - (REAL)i0);
                const float fy = (float)(yb - (REAL)j0);
                const REAL s00 = smoke[j0 * nx + i0];
                const REAL s10 = smoke[j0 * nx + i1];
                const REAL s01 = smoke[j1 * nx + i0];
                const REAL s11 = smoke[j1 * nx + i1];
                const REAL top = (1.0f - fx) * s00 + fx * s10;
                const REAL bot = (1.0f - fx) * s01 + fx * s11;
                smokeScratch[idx] = (1.0f - fy) * top + fy * bot;
            }
        }
        // 子步回拷：flow->smoke（new[] 数组）始终是"当前最新"，
        // 下一子步继续读它 → 子步间自然级联
        std::copy(smokeScratch.begin(), smokeScratch.end(), flow->smoke);
    }
    // 收尾：flow->smoke 即最终结果；smokeScratch 下帧整写覆盖，无需清零
}
```

> ⚠️ **双缓冲实现注意（必须按此写）**：`flow->smoke` 是 `REAL*`（`new[]` 分配），`smokeScratch` 是 `std::vector<REAL>`，二者**不能**做 `std::swap(flow->smoke, smokeScratch.data())`：
> 1. `smokeScratch.data()` 返回右值，`std::swap(REAL*&, REAL*&)` 无法绑定 → **编译失败**；
> 2. 即便换成指针成员间接 swap，`flow->smoke` 会指向 vector 内部缓冲区，`Release()` 中的 `delete[] flow->smoke`（[L703](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L703)）会对 vector 缓冲执行 `delete` → **UB，且 vector 析构时二次释放 → 崩溃**。
> 正确做法即上面伪码：每子步 `std::copy` 回拷（18k 个 float × 子步数，毫秒级，可忽略）。若想省拷贝，可把 `smokeScratch` 换成 `std::unique_ptr<REAL[]>` 并在 `Init` 中与 `flow->smoke` 一起 `new[]` 分配，用两个裸指针 `src/dst` 交替——**但必须保证最终 `flow->smoke` 始终指向最初 `new[]` 的那个数组**（`Release` 只 `delete[]` 它）。
>
> 更简单的落地（文档推荐的默认实现）：**不拆子步**（`substeps = 1, dt = stepsPerFrame`），整帧一次平流 + 一次 `std::copy` 收尾；子步拆分仅当 `stepsPerFrame` 大（>20 且烟迹变糊）时再启用（§3.2 方案 A/B）。

## 4. 物体冒烟（拖拽烟源）

### 4.1 烟源格点的正确选择（关键设计决策）

评估文档 §5.1 写"物体覆盖格点持续冒烟"，但**不能直接把烟注入固体格点**：

- §3.4 规定固体格点在平流中**保持自身旧值、不参与平流**。若注入到固体格点，烟会被永久"锁死"在体内，永远不会被流场带走——与"物体拖出烟尾迹"的目标直接矛盾。

**正确做法**：烟源 = **物体固体格点的流体 8 邻居**。烟一产生就在流体里，立刻被流场搬运，形成随物体移动的烟尾迹。

- 邻域格点集合可直接由 `solidCellsCache` 派生（该缓存已按 `OwnerBodyOfCell >= 0` 过滤，只含物体格点，[testMrLBM2D.cpp L1017-L1027](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L1017-L1027)）。
- 物体**释放的格点**（moving 后新变流体的旧固体格点）无需额外处理：它们在体内时其流体邻居已注入烟，释放后该格点自身就是流体且带烟，自然被带走。

### 4.2 注入条件与公式

```cpp
const REAL kSmokeMax = 1.0f;          // 浓度上限（§10）

if (smokeEnabled && (dragging || bodySmokeAlways)) {
    for (const int idx : solidCellsCache) {
        const int sx = idx % nx, sy = idx / nx;
        for (int dy = -1; dy <= 1; dy++)
            for (int dx = -1; dx <= 1; dx++) {
                if (dx == 0 && dy == 0) continue;

                if (nx2 < 0 || nx2 >= nx || ny2 < 0 || ny2 >= ny) continue;
                const int nb = ny2 * nx + nx2;
                if (flow->flag[nb] != ML_FLUID) continue;   // 只注入流体格点
                flow->smoke[nb] = std::min(flow->smoke[nb] + smokeRate, kSmokeMax);

    }
}
```

- **触发条件**：`dragging == true`（正在拖，评估文档规则 1）；`bodySmokeAlways`（可选复选框，默认 false）为 true 时**静止也持续冒烟**（评估文档"静止时按 UI 选项决定持续冒烟/停止"）。`smokeEnabled == false` 时**绝不产生烟雾**（评估文档规则 3）。
- 注入量 = `smokeRate`（现有 UI 滑块 0.001~0.1，[testMrLBM2D.cpp L2356](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L2356)），每 UI 帧一次。
- **注入不写设备**：smoke 是 host-only 场，无同步。

### 5.2 工具执行函数（统一入口）

```cpp
void ApplyToolAt(float cx, float cy, InteractionTool tool, bool pressed) {
    // cx/cy = mouseFieldX/Y；pressed = 本次是否按下（区分 hover 弱注入）
    const int nx = definition.nx, ny = definition.ny;
    const int R = (int)std::ceil(smokeBrushRadius);
    injectedForceCells.clear();   // 成员（§2）：仅 Blow/Vortex 填充，供 ClearInjectedForces 用

    for (int y = (int)cy - R; y <= (int)cy + R; y++)
        for (int x = (int)cx - R; x <= (int)cx + R; x++) {
            if (x < 1 || y < 1 || x >= nx - 1 || y >= ny - 1) continue;
            const int idx = y * nx + x;
            const float dx = (float)x - cx, dy = (float)y - cy;
            if (dx * dx + dy * dy > smokeBrushRadius * smokeBrushRadius) continue;
            // 边界格点（INLET/OUTLET/WALL_*）禁止涂抹（沿用"边界禁画"原则）
            if (flow->flag[idx] != ML_FLUID) continue;

            switch (tool) {
            case InteractionTool::PaintSmoke:
                flow->smoke[idx] = std::min(flow->smoke[idx] +
                    (pressed ? smokeRate : smokeRate * 0.25f), kSmokeMax);
                break;
            case InteractionTool::EraseSmoke:
                flow->smoke[idx] = 0.0f;   // 刮烟
                break;
            case InteractionTool::Blow:      // §5.5，falloff 由调用方给出
            case InteractionTool::Vortex:
                // 写入 flow->forcex/forcey（§5.5 公式），并收集格点
                injectedForceCells.push_back(idx);
                break;
            case InteractionTool::None:
            default:
                break;
            }
        }
    if (!injectedForceCells.empty())
        SyncCellsToDevice(solver, 0, injectedForceCells, /*syncFlags=*/false);
}
```

> 注：笔刷半径用**圆判据**（`dx²+dy² ≤ R²`），与全局 `obstacleShape` 解耦——笔刷形状不应随物体形状设置变化（与手绘固体 §6.3 同一约定）。

### 5.3 力注入的持久性与清零（关键稳定性设计）

`forcex / forcey` 由 host 全权管理：kernel 只读（[mrLbmSolverGpu2D.cu L69-L72](file:///d:/Code/CG/Phy/home2d/inc/2D/gpu/mrLbmSolverGpu2D.cu#L69-L72)），host 端 `WriteMoments2D` 会清零（[LbmCases2D.cpp L309-L310](file:///d:/Code/CG/Phy/home2d/src/LbmCases2D.cpp#L309-L310)）。设计：

1. **写入**：`ApplyMouseEffects` 内向 brush 半径内流体格点写 `forcex/forcey`，收集到成员 `injectedForceCells`，一次 `SyncCellsToDevice(solver, 0, injectedForceCells, false)`（该函数会同时拷 `fMom/fMomPost/forcex/forcey`，同步循环见 [testMrLBM2D.cpp L253-L277](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L253-L277)）。
2. **作用窗口**：力在整段 `stepsPerFrame` 次 LBM 迭代内持续作用（每步的碰撞都读它）。
3. **清零**：LBM 循环后、平流前，新增 `ClearInjectedForces()`：把 `injectedForceCells` 内格点的 `forcex/forcey` 写回 0 并再次 `SyncCellsToDevice`。保证力"只活一帧"，下一帧不残留。

```cpp
// §5.3 清力：与 WriteMoments2D（只清边界/固体格点）互补——本函数只清 brush 写入的流体格点
void LbmApp::ClearInjectedForces() {
    if (injectedForceCells.empty()) return;
    for (const int idx : injectedForceCells) {
        flow->forcex[idx] = 0.0f;   // 仅清本帧注入过的格点，不整场扫描
        flow->forcey[idx] = 0.0f;
    }
    SyncCellsToDevice(solver, 0, injectedForceCells, /*syncFlags=*/false);
    injectedForceCells.clear();
}
```

> **与 `WriteMoments2D` 无冲突**：`WriteMoments2D` 只在边界刷新（`RefreshDemoCaseBoundaries`）与固体重分类（`ApplyObstaclePoses` 内写壁面矩）路径调用，作用格点是 INLET/OUTLET/WALL_*/ML_SOLID；brush 力只写 `ML_FLUID` 格点（§5.2 已过滤）。二者作用域不相交，谁先谁后都安全。

> **无害性论证（host/device 同步不变式）**：`SyncCellsToDevice` 同步 `force` 时会顺带把该范围 host 端 `fMom/fMomPost` 拷到设备。此时 host `fMom` 是上一帧 `CopyMomentsFromDevice` 拷回的最新值，设备端 `fMom` 也是同一时刻的最新值——**两者相等**，覆盖写入是幂等的、无副作用。该不变式依赖"每帧恰好一次 `CopyMomentsFromDevice`"，实现时不得删除 `Step()` 中该调用。

**力幅度上限**：写入前 clamp 到 `Fmax = 0.02f`（与 UI `blowStrength` 滑块上限一致，[testMrLBM2D.cpp L2357](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L2357)）。量级依据：入口速度 `uy = 0.08~0.10`，`F = 0.02` 的力修正 `0.5·F/ρ ≈ 0.01`，与主流速同量级但远小于 `kMaximumWallSpeed = 0.25`（[L41](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L41)），配合 `omega ≈ 1.5~2` 无发散风险。**禁止**直接写入未 clamp 的力（评估文档 §5.3-3：局部速度过冲是流场发散的头号原因）。

### 5.4 hover 画烟（规则 1：未按下也画烟）

- 条件：`smokeEnabled && activeTool == PaintSmoke && !IsOverUiPanel(mouseScreenX, mouseScreenY, layout) && !UiWantsCaptureMouse()`。
  - ⚠️ **`layout` 的来源**：`ApplyMouseEffects` 是 `LbmApp` 成员、`Step()` 无参，窗口句柄不在作用域内。`layout` 必须现算：`const UiLayout layout = CurrentLayout(appWindow);`（[L1893](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L1893)，窗口可能已缩放不能缓存），`appWindow` 是 §2 新增成员，由 `main()` 中 `CreateWindowExW` 成功后赋值。
- 执行：`ApplyToolAt(mouseFieldX, mouseFieldY, PaintSmoke, /*pressed=*/false)`，注入量为 `smokeRate * 0.25f`（弱注入，防止不点击也快速填满烟场）。
- ⚠️ **必须查面板豁免**：`WM_MOUSEMOVE` 会无条件更新 `mouseFieldX/Y`（[L2744-L2752](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L2744-L2752)），若 hover 画烟不查豁免，鼠标滑过右侧 UI 面板时会持续在面板下方格点画烟。
- **特性说明（不是 bug）**：`ApplyMouseEffects` 由 `WM_TIMER` 每 UI 帧调用一次，鼠标**静止不动**时 `mouseFieldX/Y` 不变、hover 条件仍成立 → 光标停留处会持续弱喷烟、被流场拖成烟带。这正是"画笔 = 持续喷烟"的预期语义；若想改为"仅移动时画烟"，可记录 `prevMouseScreenX/Y` 与当前相等时跳过注入（§5.5 的差分成员已提供该信息，实现时自选）。
- 关闭烟雾效果时（`smokeEnabled == false`）hover **不产生任何烟雾**（规则 3）。

### 5.5 Blow / Vortex / Erase 细则

**Blow（吹风）**：写入定向体力。方向 = 鼠标移动方向（由 `mouseScreenX/Y` 的帧间差分归一化，未动时回退 `(0, +1)`——主流方向），强度 `blowStrength`：

```cpp
// §5.5 差分更新：必须在 ApplyMouseEffects 开头无条件执行（无论本次是否吹风），
// 保证差分是"帧间增量"而非"按下以来总位移"
const int dScreenX = mouseScreenX - prevMouseScreenX;
const int dScreenY = mouseScreenY - prevMouseScreenY;
prevMouseScreenX = mouseScreenX; prevMouseScreenY = mouseScreenY;
float dirX = 0.0f, dirY = 1.0f;                 // 未动 → 主流方向（Karman/Jet 均 +y 上行）
if (dScreenX != 0 || dScreenY != 0) {
    const float len = sqrtf((float)(dScreenX*dScreenX + dScreenY*dScreenY));
    dirX = (float)dScreenX / len; dirY = (float)dScreenY / len;
}

// 写入（在 ApplyToolAt 的 Blow 分支内，dx/dy = 笔刷相对偏移）
const float falloff = std::max(0.0f, 1.0f - sqrtf(dx*dx+dy*dy) / smokeBrushRadius);
forcex[idx] = ClampFloat(dirX * blowStrength * falloff, -kFmax, kFmax);
forcey[idx] = ClampFloat(dirY * blowStrength * falloff, -kFmax, kFmax);
```

> 屏幕差分直接用作格点方向是近似：`ScreenToFieldPoint` 的纵横缩放比例在窗口保持宽高比时一致，忽略缩放误差即可（可视化工具不追求精确）。

**Vortex（旋涡）**：切向体力场（圆心 = 笔刷中心）：

```cpp
const float dist = std::max(1.0e-4f, sqrtf(dx*dx+dy*dy));
const float falloff = std::max(0.0f, 1.0f - dist / smokeBrushRadius);
forcex[idx] = ClampFloat(-k * (dy / dist) * falloff, -kFmax, kFmax);  // 逆时针
forcey[idx] = ClampFloat( k * (dx / dist) * falloff, -kFmax, kFmax);
// k 取 blowStrength 同量级（默认 0.004，与 UI 一致）
```

- 触发：中键按下 = Vortex；`Shift` + 左键 = Blow（覆盖 `activeTool`，与评估文档 §5.3 一致）。
- Shift 检测用 `GetAsyncKeyState(VK_SHIFT) & 0x8000`（[L2802](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L2802) 附近无 Shift 消息，且 `GetKeyState` 依赖消息队列状态、在 `WM_TIMER` 回调里不可靠；`GetAsyncKeyState` 读取真实按键状态，与窗口焦点无关）。
- Erase 不依赖 `smokeEnabled` 也可执行（刮掉现有烟），但 `smokeEnabled == false` 时烟场恒为 0，擦与不擦无差别——为语义干净，Erase 也门控在 `smokeEnabled` 下（§10 稳定性条目 3）。

### 6.2 混色方案

在基础色 `(r, g, b)` 计算完成后、写 `pixels` 之前插入：

```cpp
// 非固体格点才混烟（固体保持深色，见 §0 现状）；壁面烟恒 0，混不混无差别
if (flow->flag[index] != ML_SOLID) {
    const float s = ClampFloat(flow->smoke[index] * kSmokeColorScale, 0.0f, 1.0f);
    if (s > 0.0f) {
        const float sr = 0.90f, sg = 0.90f, sb = 0.86f;   // 暖灰白烟色
        r = r * (1.0f - s) + sr * s;
        g = g * (1.0f - s) + sg * s;
        b = b * (1.0f - s) + sb * s;
    }
}
```

- `kSmokeColorScale`（建议 5~8）：把 `[0, 1]` 浓度映射到混合强度。量级验证：`smokeRate = 0.02`，拖拽 30 帧累计 ≈ 0.6 → `s ≈ 0.5`，烟迹清晰可见；`kSmokeMax = 1.0` 封顶防饱和。
- **色带选择理由**：暖灰白对 MAGMA（深蓝→黄）与涡量色（青/品红系）的底层色干扰最小，观感接近真实烟。若想更醒目可改冷白 `(0.85, 0.90, 0.95)`，实现时取常量即可。
- 涡量模式下烟会压暗涡结构颜色——这是"烟雾叠加显示"的预期行为；如需"纯烟视图"可在 FIELD VIEW 下拉加第三项（YAGNI，本期不做）。

## 10. 数值稳定性与健壮性清单

1. **力必须 clamp**：`|F| ≤ Fmax = 0.02`（§5.3）。局部速度过冲是本 LBM 格式发散的头号原因（评估文档 §5.3-3）。
2. **烟浓度 clamp**：注入 `smoke[idx] = min(smoke[idx] + rate, kSmokeMax = 1.0f)`；双线性插值是凸组合，天然不超界。
3. **Erase 门控**：`smokeEnabled == false` 时 Paint/Erase/hover 全不执行（规则 3）；Blow/Vortex 恒可用（规则 4）；拖动物体恒可用（规则 1/2）。
4. **边界禁画**：工具只作用于 `ML_FLUID` 格点；`INLET/OUTLET/WALL_*` 一律跳过（§5.2），防破坏边界矩。
5. **固体格点烟不参与平流**（§3.4）：既防"烟透壁"，也保证烟源注入必须落在流体格点（§4.1）。
6. **平流数值守卫**：非有限速度或 `|u| > 1` 跳过该格点（§3.6），防 NaN 蔓延。
7. **双缓冲纪律**：每子步用 `std::copy(smokeScratch → flow->smoke)` 回拷，**`flow->smoke` 必须始终指向 `new[]` 分配的数组**（`Release` 的 `delete[]` 只对它有定义，§3.7）；禁止 `std::swap(REAL*, vector.data())`。`smokeScratch` 在 `Init` 中与网格同生命周期 resize；重建算例（`Release + Init`）后 `flow->smoke` 已清零、`smokeScratch` 重新分配，无残留。
8. **host/device 同步不变式**：不删除 `Step()` 中的 `CopyMomentsFromDevice`（§5.3 论证依赖它）；smoke 不进任何同步函数（§2）。
9. **不触碰 `.cu`**：kernel 零改动；`mrFlow2D` 结构体大小已含 `smoke` 指针，`mlDeepCopy` 按方案 B 自动处理（§0.1 第 4 条）。
10. **hover 豁免**：hover 画烟必须同时查 `IsOverUiPanel` 与 `UiWantsCaptureMouse`（§5.4），否则鼠标滑过 UI 面板会误画烟。
11. **`injectedForceCells` 成员纪律**：它是 `LbmApp` 成员（§2），`ApplyToolAt` 开头 clear、`ClearInjectedForces` 末尾 clear、`Init` 复位时 clear（§5.2/§5.3）；**禁止用局部变量收集**（`ClearInjectedForces` 跨函数不可见，编译能过但运行必漏清力）。
12. **`appWindow` 必须有效**：`main()` 中 `CreateWindowExW` 成功后必须 `gApp.appWindow = window;`；hover 豁免现算 `CurrentLayout(appWindow)`，句柄为 NULL 时 `GetClientRect(NULL)` 得 0 尺寸 → `ComputeLayout` 内部除法出现 0/0（§5.4）。

## 12. 验收清单（对照评估文档 §5.1 四条规则）

1. **拖动物体冒烟**：`smokeEnabled` 下拖动 Karman 圆柱，物体覆盖区持续冒烟且被流场拖成尾迹；静止时不冒（默认 `bodySmokeAlways = false`）。
2. **画笔与力源**：`smokeEnabled` 下左键画烟、右键刮烟、中键旋涡、Shift+左键吹风；Jet+Smoke 预设下画笔效果明显（无物体场景）。
3. **关闭烟雾效果**：`smokeEnabled = false` 时，鼠标滑动（未按下）不产生任何烟雾；已存在的烟仍被流场运走、自然消散于出口。
4. **左键交互始终可用**：`smokeEnabled = false` 时左键仍能拖动物体、Blow/Vortex 力源仍生效（吹散残烟）。
5. **稳定性**：连续拖动 + 反复吹风/旋涡 5 分钟无发散、无 NaN；暂停（Space）时烟冻结，恢复后续走。
6. **显示**：烟色叠加在速度/涡量两种视图下均正确；固体与壁面不显示烟色；出口无烟柱堆积。
7. **回归**：不开启任何烟雾功能时，原 Karman/Jet 行为与实现前完全一致（kernel 未改动，烟场为空即透明）。
