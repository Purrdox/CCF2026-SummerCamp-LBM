enum class ObstacleShape { Circle, Box, Diamond }; // 全局形状，所有物体共用

struct RigidBody {

- 原有 `obstacleX/Y/TargetX/Y/VelocityX/Y` 字段迁移进 `RigidBody`。

## 2. 功能 1：可切换物体类型

### 2.1 需求
- 圆柱之外可切换为其它形状（方块、菱形等），可运行时切换（UI 下拉 / 快捷键）。
- 物体系统**统一为多物体**（`bodyCount ≥ 1`，无单物体特例路径）：可摆放多个物体，按组合 A 约束实现（全局单一形状 + 互不重叠 + 不旋转 + 固定上限 4 个 + 仅鼠标拖动）。

### 2.2 实现方案（组合 A，≈ ★★☆☆☆）

> 物体从第一天就以 `std::array<RigidBody, kMaxBodies>` 数组实现；`bodyCount == 1` 只是数组长度为 1 的特例，代码路径完全一致。以下 S1~S7 为可直接照做的实现清单。

#### S1 数据结构

```cpp
const int kMaxBodies = 4;                      // 固定数量上限

struct RigidBody {
    float x, y;      // 中心位置
    float vx, vy;    // 壁面速度（每步 = 位移 / stepsPerFrame）
    float tx, ty;    // 目标点（鼠标/键盘写入）
    float radius;    // 半径；Box 为半宽=半高
    bool selected;   // 鼠标/UI 选中态（拖动 + 高亮）
};
```
- `LbmApp`：`std::array<RigidBody, kMaxBodies> bodies; int bodyCount = 1; int selectedBody = 0;`
- **全局形状**：`ObstacleShape obstacleShape;`（切换对象，所有物体同形状）；不设 `angle`（不旋转）。
- 删除旧字段 `obstacleX/Y/TargetX/Y/VelocityX/Y`；`Init()` 中 `bodies[0] = { definition->obstacleStartX, definition->obstacleStartY, 0, 0, definition->obstacleRadius, true };`，其余物体由 UI 添加（S7）。

#### S2 形状判据

```cpp
bool IsObstacleCell(ObstacleShape shape, int x, int y,
                    float cx, float cy, float radius) {
    const float dx = x - cx, dy = y - cy;
    switch (shape) {
    case Circle:  return dx * dx + dy * dy <= radius * radius;
    case Diamond: return fabsf(dx) + fabsf(dy) <= radius;
    case Box:     return fabsf(dx) <= radius && fabsf(dy) <= radius;
    }
    return false;
}
```
（改 [LbmCases2D.cpp](file:///d:/Code/CG/Phy/home2d/src/LbmCases2D.cpp#L219-L240) `IsDemoCaseObstacleCell`）

#### S3 统一格点分类

```cpp
bool IsAnyObstacleCell(const RigidBody* b, int count,
                       ObstacleShape shape, int x, int y) {
    for (int i = 0; i < count; i++)
        if (IsObstacleCell(shape, x, y, b[i].x, b[i].y, b[i].radius))
            return true;
    return false;
}
```
- 互不重叠 ⇒ 每格点至多命中一个物体，union 判定无归属歧义。
- 1024² 时先算各物体包围盒 `[cx±r]×[cy±r]`、只在这些区域做判据；96×192 下可省略。

#### S4 流固耦合 `ApplyObstaclePoses`（唯一动流固耦合处）

- 签名：`ApplyObstaclePoses(const float newX[], const float newY[], const float wallUx[], const float wallUy[])`（数组长度 = bodyCount）。
- 内部流程与单物体**逐行一致**（[testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L735-L893)）：全量重分类 → released/solid → 释放重建 → 新增 solid 写壁面矩 → touched → `SyncCellsToDevice`，只改两处：
  1. 分类：`IsDemoCaseObstacleCell(...)` → `IsAnyObstacleCell(bodies, bodyCount, obstacleShape, x, y)`；
  2. 新增固体格点写壁面矩前，先反查所属物体：

```cpp
int OwnerBodyOfCell(const RigidBody* b, int count,
                    ObstacleShape shape, int x, int y) {
    for (int i = count - 1; i >= 0; i--)    // 互不重叠 ⇒ 命中唯一
        if (IsObstacleCell(shape, x, y, b[i].x, b[i].y, b[i].radius))
            return i;
    return -1;
}
// 写壁面矩处：
//   const int owner = OwnerBodyOfCell(bodies, bodyCount, obstacleShape, sx, sy);
//   writeBoundaryMoments(solidIdx, neighbor, wallUx[owner], wallUy[owner]);
```
- **不需要**"持续 ghost 刷新 / 重叠归属"——组合 A 的核心收益。
- 释放判定基于 flag，与物体数量无关，原样保留。

#### S5 受力分组

- `ComputeSolidLoads`：对每个"固体邻居"执行 `owner = OwnerBodyOfCell(...)`，累加到 `bodyForceX[owner]/bodyForceY[owner]/bodyTorque[owner]`；力矩参考点由固定 `(obstacleX, obstacleY)` 改为 `bodies[owner].x/y`（对应现有 [testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L990-L992) 一处替换）。
- 平滑滤波按物体：`bodyForceX[i] += blend * (raw - bodyForceX[i])`。
- 面板显示：选中物体一行（`bodies[selectedBody]`）即可，无需 4 行全列。

#### S6 移动与拖动

- 键盘方向键（现有 `UpdateObstacleTarget`）：目标改为 `bodies[selectedBody].tx/ty`。
- 鼠标拖动（§3.2）：命中遍历 → `selectedBody = i` → `WM_MOUSEMOVE` 写 `bodies[i].tx/ty`。
- `AdvanceObstacle` → `AdvanceObstacles()`：对每个物体循环"目标逼近 + `kMaximumWallSpeed` 限速 + `move/stepsPerFrame` 换算"（原逻辑 [testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L895-L926) 套循环即可）。
- **互不重叠校验（约 10 行）**：更新 `tx/ty` 后，若与其它物体中心距离 < `r_i + r_j`，把目标点沿连线推回最近合法位置，否则拒绝更新。

#### S7 绘制与 UI

- 绘制：遍历 bodies，按 `obstacleShape` 画轮廓（圆 / 正方形 / 菱形分支，改 [testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L1303-L1334) `DrawObstacleTarget` 为循环）；`selected` 物体描边高亮。
- UI（功能 3）：物体数量 `+/-`（加物体时校验不重叠）、选中列表（单选）、全局形状下拉、每物体位置/半径滑块。

> **实现顺序**：S1 → S2/S3 → S4（先让多个静态物体正确参与流场）→ S6 拖动 → S5 受力 → S7 UI。每个小步都可编译可演示。
> **难度总结**：≈ ★★☆☆☆。无单物体特例路径，整个物体系统即数组版本。

### 2.3 未来升级路径（按需解锁，本期不预留）

> 完整版（允许重叠 / 逐物体形状 / 旋转）难度为 ★★★★☆，本期不做。组合 A 已砍掉其全部难点（重叠归属、持续 ghost 刷新、逐物体形状/旋转）。若后续出现以下需求，再按表解锁：

| 逐物体受力同时显示 | 遍历显示 4 组力/力矩 | +0.5★ |
| 键盘同时控制多个物体 | 方向键 + `Shift`+方向键切换物体 | +0.5★ |

> 结论：本期**不预留**上述升级接口（YAGNI），等真实需求出现再按表解锁。

## 3. 功能 2：鼠标拖动场内物体（多物体）

### 3.1 需求
- 鼠标按住物体直接拖动；物体系统为多物体数组（§2），拖动作用于**选中物体**（`selectedBody`），一次拖一个。

### 3.2 实现步骤

1. **命中检测**：`WM_LBUTTONDOWN` → 光标转格点坐标 → `IsAnyObstacleCell(bodies, bodyCount, obstacleShape, gx, gy)` 命中（或距离 ≤ r + 3 格容差）；从"最后遍历者/最近者"优先，`selectedBody = i; dragging = true`。
2. **拖动**：`WM_MOUSEMOVE` 时若 `dragging` → `bodies[selectedBody].tx/ty = clamp(光标格点)`（clamp 范围沿用现有 margin 逻辑，[testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L715-L723)）。
3. **运动执行**：复用 §2.2-S6 的 `AdvanceObstacles()` 逐物体循环（目标逼近 + `kMaximumWallSpeed` 限速 + `stepsPerFrame` 换算 + 互不重叠校验）。
4. **释放**：`WM_LBUTTONUP` → `dragging = false`；被拖物体保持当前位置，高亮恢复。
5. **与键盘共存**：方向键与鼠标都写 `bodies[selectedBody].tx/ty`，按时间顺序自然覆盖。

> **难度**：★★☆☆☆（中偏易）。命中遍历 + 选中态管理 + 消息映射约 60 行，运动复用现有管线。

### 3.3 简化方案
- 一次只允许拖动一个物体（推荐，无并行拖动复杂度）。
- 拖动时若鼠标移到 UI 面板区域（`panel` 矩形内）则忽略，避免与功能 3 控件抢事件。

### 4.4 保存 / 读取
- 文件格式：`params.ini`，`key=value` 每行一项（**不引入 JSON 库**，保持工程零依赖）：

- 启动时若 `params.ini` 存在则自动加载；UI 提供"保存 / 加载 / 恢复默认"按钮。非法值回退默认并提示。

## 5. 功能 4：烟雾交互模式

### 5.1 需求理解（四条规则的组合）
1. **拖动物体时**：物体整体作为"移动烟源"，其覆盖格点持续冒烟，烟雾被流场带走 → 物体拖出烟尾迹。
2. **无物体 + 鼠标滑动**：采用"交互式烟雾画笔与力源工具"（原创意 A：画烟/刮烟/吹风/旋涡）。
3. **关闭烟雾效果**：鼠标滑动（未按下）不产生任何烟雾。
4. **左键保持按下**：即使关闭烟雾效果，左键点击**仍可交互**（拖物体 / 吹风 / 旋涡等力源工具始终可用）。

### 5.2 交互状态机（与功能 2 合并实现）
```
鼠标移动(未按下) ─ smokeEnabled? → 画笔 hover 效果（画烟）
                └ 否则 → 无操作
左键按下 ─ 命中物体? → 拖动物体 + 物体冒烟(若 smokeEnabled)
        └ 未命中 → smokeEnabled? → 画笔/力源工具（画烟/吹风/旋涡）
                 └ 否则 → 力源工具（吹风/旋涡，不生成烟雾）
左键保持 → 每帧持续执行当前工具（注入/力）
左键释放 → 工具结束
```
- 说明：规则 4 由"力源工具不依赖 smokeEnabled"满足——左键交互（拖/吹/旋涡）始终有效，仅"烟雾生成"受开关控制。

### 5.3 实现步骤
1. `smokeEnabled` 布尔（功能 3 预设的一部分）。
2. **物体冒烟**：拖动期间每 UI 帧向物体覆盖格点 `smoke[idx] += rate`。格点集可直接用 `ApplyObstaclePoses`（§2.2-S4）收集的 solidCells 缓存，或遍历 `IsAnyObstacleCell` 求交；静止时按 UI 选项决定"持续冒烟 / 停止"。
3. **画笔/力源工具**（原"创意 A：Flow Brush"设计）：
   - 左键画烟、右键刮烟（`smoke[idx] *= 0`）、`Shift`+左键吹风（写 `forcex/forcey`）、中键旋涡。
   - **所有"鼠标→体力"写入必须带上限裁剪**（参考 `kMaximumWallSpeed`），防止局部速度过冲致流场发散。
4. 工具选择：功能 3 UI（当前工具下拉、笔刷半径、注入率、吹风强度）。
5. 调用位置：`WM_MOUSEMOVE/LBUTTON*` 处理器内更新"目标格点/是否按下"，`Step()` 前的 `ApplyMouseEffects()` 每帧统一执行注入/力写入（保证与 LBM 步解耦、顺序一致）。

> **难度**：★★★☆☆（中）。烟雾场、鼠标输入、物体系统均为已建基础设施；新增的是"状态机 + 物体冒烟注入"，难点在交互手感与数值稳定性（上限裁剪）。

### 5.4 简化方案
- 先只做"左键画烟 + 拖物体冒烟"，刮烟/吹风/旋涡作为第二批（它们是同一写入路径，按需添加）。
- 物体冒烟频率：每帧注入比每 LBM 步注入便宜且效果差异小，先每帧。

## 6. 功能 5：Ctrl 区域放大 + 格点调试信息

### 6.1 需求
- 按住 `Ctrl`：进入选中模式；左键单击某格点 → 显示该格点**全部数据与调试信息**，直接**覆盖绘制在流场表面**；松开 `Ctrl` 后调试信息消失。
- 附带"选中某块区域并放大"能力（放大镜 / 局部放大视图）。

### 6.2 实现步骤

1. **Ctrl 跟踪**：`WM_KEYDOWN/WM_KEYUP` 的 `VK_CONTROL` → `bool ctrlHeld`。
2. **选中格点**：`ctrlHeld && WM_LBUTTONDOWN` → 光标转格点坐标，记录 `debugCellX/Y`。
3. **数据读取**：host 端 `flow->fMom[idx*6+0..5]`（rho/ux/uy/pixx/piyy/pixy）、`flow->flag[idx]`、坐标与 `iteration` 每帧在 `CopyMomentsFromDevice` 后即最新。
   - 注意：`forcex/forcey` 的 host 值不一定与设备同步（设备端每次核迭代后更新）。调试信息**默认不显示 force**，或把 force 加入 `CopyMomentsFromDevice`（增加一次 D2H 拷贝，代价小，按需取舍）。
4. **覆盖绘制**：`Render()` 中在 `DrawField` 之后、`DrawPanel` 之前插入 `DrawDebugOverlay()`：
   - 半透明黑底矩形 + `DrawText` 多行文本（`x, y, flag名, rho, ux, uy, pixx, piyy, pixy, iteration`）。
   - 用现有位图字体（[testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L1216-L1227)），无需新字体。
   - `!ctrlHeld` 时跳过绘制（信息自动消失）。
5. **区域放大**（两种方案，A 更简）：
   - **A. 局部放大镜（推荐）**：Ctrl 模式下以光标为中心，把 field 纹理的 `±8` 格子区域用更大的 quad 绘制到画面角落——仅需修改 `glTexCoord` 子区域 + 固定大小 quad，**约 30 行，无新数据**。
   - **B. 框选放大**：Ctrl+拖动框选矩形，选中区域填满画面（改 `glOrtho` + 纹理坐标），交互稍复杂，留作可选。

### 6.3 难度评估
> **★★☆☆☆（中偏易）**。调试信息本身是"读数组 + 画文本"；放大镜是纯渲染层的纹理子区域绘制。风险点仅在 force 数据的设备/主机一致性，按 §6.2-3 取舍即可规避。

## 7. 功能 6：手绘固体模式（与预制图形并列的附加模式）

### 7.1 需求
- 新增**编辑模式**选项 `EditMode { PresetObjects, FreehandSolid }`，与"是否使用预制图形"并列，运行时切换（UI 下拉）。
- 手绘模式：左键按住 = 画笔（笔刷半径内格点涂成**固体**）；橡皮工具 / 右键 = **手动擦除**。
- 手绘形状**不可移动**：无 `vx/vy`、不进 `AdvanceObstacles`、不算受力——本质是"静态固体 mask 层"。
- 与预制物体**可共存**：mask 与 `IsAnyObstacleCell` 合并判定；重叠区**物体优先**。

### 7.2 实现方案（数据 + 合并 + 画笔/擦除，全部复用既有基础设施）

1. **数据层**：`LbmApp` 新增 `std::vector<uint8_t> drawnMask;`（长度 = nx·ny）+ `EditMode editMode;` + 笔刷参数（半径、画/擦标志）。与 `RigidBody` 数组并存，互不侵入。
2. **流固耦合（唯一核心改动）**：`ApplyObstaclePoses`（§2.2-S4）重分类判定改为
   `isSolid = drawnMask[idx] || IsAnyObstacleCell(...)`；`InitializeDemoCase` 同步合并。released/solid 追踪、邻居平均重建（`AverageNeighborMoments`）、`SyncCellsToDevice` 全部原样复用。
3. **画笔**：复用 §1.3 鼠标系统与功能 2 状态机——左键按住，把笔刷半径内增量格点写壁面矩（`wall = 0`）→ 加入 touched → 去重后一次性同步。
4. **擦除**：`drawnMask[idx] = 0` → 格点恢复 `baseFlag` → 走现有 released 重建 → 同步。
5. **受力**：`ComputeSolidLoads` 对固体邻居反查 `owner`，`owner == -1`（手绘格点）**跳过**累加。
6. **UI**：编辑模式下拉 + 工具单选（Paint/Erase）+ 笔刷半径滑块 + `[Clear all freehand]` 按钮，并入功能 3 的 TOOLS 分组。

### 7.3 关键设计点（稳定性）
- **矩合法性**：新画固体必须写合法矩（平衡矩 `rho=1, u=0` 即可，静态壁面足够稳定），**禁止只改 flag**，否则 GPU pull streaming 读到垃圾 → 流场发散。
- **边界禁画**：`ML_INLET / ML_OUTLET / ML_WALL_*` 格点不允许写入 mask。
- **批处理**：单次鼠标移动的增量格点去重后再同步，避免逐像素 memcpy。
- 笔刷半径限制 1~8（单帧约 ≤200 格，开销可忽略）。

### 7.4 难度评估
> **★★☆☆☆ ~ ★★★☆☆（中偏易）**，与功能 2 相当、略高。**不可移动**砍掉了壁面速度 / 目标逼近 / 互不重叠校验 / 受力归属等全部动态难点；新增难点集中在"与物体重分类合并 + 擦除重建"，二者均有现成机制（全量重分类 + `AverageNeighborMoments`）。简化选项：画笔用平衡矩而非非平衡外推，可再减约十几行。实施成本约 +200~300 行，建议与功能 4/5 同批实施（M6，见 §8）。
