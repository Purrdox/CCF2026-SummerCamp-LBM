# Home2D 扩展功能实现方案与难度评估（重构版）

> 评估对象：`LBM_MRLBM` 工程（D2Q9 矩格式 LBM + CUDA + OpenGL 实时显示）。
> 本文档围绕 **5 个确定要实现的功能**给出详细实现细节、分步骤实施路径与难度评估。
> 原则：凡有"效果相近但更易实现"的方案，均给出简化建议；文末附"仅需简单修改即可实现"的额外扩展清单。

## 0. 需求总览与难度总表

| # | 功能 | 难度（单个物体） | 难度（多个物体） | 依赖 |

| 2 | 鼠标拖动场内物体 | ★★☆☆☆ 中偏易 | ★★☆☆☆（组合 A） | 功能 1 的物体系统、鼠标输入 |

**核心判断**：功能 1/2 的"单个物体"与"多个物体"难度差异，不在于形状判据或拖动逻辑本身，而在于**数据与流固耦合管线是否从"单例标量"重构为"数组系统"**。因此公共基础设施（§1）一律按"数组可扩展"设计，单物体只是数组长度为 1 的特例。
**多物体难度提示**：多物体正式方案为**组合 A**（§2.3）：全局单一形状 + 互不重叠 + 不旋转 + 固定上限 4 个 + 仅鼠标拖动，难度 ≈ ★★☆☆☆。完整版（重叠/逐物体形状/旋转）难度为 ★★★★☆，本期不做，未来按 §2.4 升级表按需解锁。

## 1. 公共基础设施（先行实施，多功能共享）

### 1.1 运行时参数结构（功能 1/3/4 共享）
- 现状：`DemoCaseDefinition` 是 const 结构，默认值写死在 `kCases[]`（[LbmCases2D.cpp](file:///d:/Code/CG/Phy/home2d/src/LbmCases2D.cpp#L12-L66)），`LbmApp` 持 `const DemoCaseDefinition* definition`（[testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L582)）。
- 改造：
  1. 去掉 `const`，`LbmApp` 改为持有**可变实例** `DemoCaseDefinition definition;`。
  2. `GetDemoCaseDefinition` 改为 `GetDefaultDefinition(DemoCaseId)` 返回拷贝。
  3. 所有 `definition->xxx` 改为 `gApp.definition.xxx`（约 30 处，机械替换）。
- 收益：功能 3 的 UI 直接改实例字段即可"热更新"（多数参数每帧被读取，见 §4.2）。

### 1.2 物体数据结构（功能 1/2/4 共享，组合 A 版）
> 多物体正式方案采用**组合 A**（见 §2.3）：全局单一形状 + 互不重叠 + 不旋转 + 固定上限 + 仅鼠标拖动。数据结构按此简化设计。

```cpp
enum class ObstacleShape { Circle, Box, Diamond }; // 全局形状，所有物体共用
const int kMaxBodies = 4;                          // 组合 A：固定数量上限

struct RigidBody {
    float x, y;      // 中心位置
    float vx, vy;    // 壁面速度（每步 = 位移 / stepsPerFrame）
    float tx, ty;    // 目标点（鼠标/键盘写入）
    float radius;    // 半径（Circle/Diamond 半径；Box 为半宽=半高）
    bool selected;   // 鼠标/UI 选中态（拖动 + 高亮）
};
```
- `LbmApp` 用 `std::array<RigidBody, kMaxBodies> bodies;` + `int bodyCount; int selectedBody;`；单物体 = `bodyCount == 1`，**同一套代码**。
- 形状 `obstacleShape` 为全局设置（可切换）；`angle` 不引入（不旋转）。
- 原有 `obstacleX/Y/TargetX/Y/VelocityX/Y` 字段迁移进 `RigidBody`。

## 2. 功能 1：可切换物体类型

### 2.1 需求
- 圆柱之外可切换为其它形状（方块、菱形等），可运行时切换（UI 下拉 / 快捷键）。
- 分别评估"限一个"与"摆放多个"的难度。

### 2.2 实现步骤（单个物体）

1. **形状枚举与参数**（[LbmCases2D.h](file:///d:/Code/CG/Phy/home2d/src/LbmCases2D.h#L19-L45)）
   - 加**全局** `ObstacleShape obstacleShape;`（所有物体共用，多物体时同形状，见 §2.3）。
   - Box 用 `radius` 作为半宽=半高（正方形），不引入 `halfW/halfH`（组合 A 简化；后续需要矩形时再扩展）。

2. **形状判据**（核心，改 [LbmCases2D.cpp](file:///d:/Code/CG/Phy/home2d/src/LbmCases2D.cpp#L219-L240) `IsDemoCaseObstacleCell`）
   - 抽出 `bool IsObstacleCell(shape, x, y, cx, cy, radius)` 按形状分派（**全局单形状，无 angle**）：
     - Circle：`(x−cx)²+(y−cy)² ≤ r²`（现有代码原样保留）
     - Box：`|x−cx| ≤ r && |y−cy| ≤ r`（半宽=半高=r 的正方形，先不做旋转）
     - Diamond：`|x−cx| + |y−cy| ≤ r`
   - 单物体调用 `IsObstacleCell(obstacleShape, x, y, bodies[0].x, bodies[0].y, bodies[0].radius)`；多物体用 §2.3 的 `IsAnyObstacleCell`。

3. **绘制**（[testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L1303-L1334) `DrawObstacleTarget`）
   - 按 shape 分支画 `GL_LINE_LOOP`：圆（现有 48 段）/ 轴对齐正方形（4 顶点）/ 菱形（4 顶点）。组合 A 不旋转，无角度变换。

4. **运行时切换**
   - 快捷键（如 `C` 循环切换）或功能 3 的 UI 下拉；切换后调用一次 `ApplyObstaclePoses(...)`（§2.3-S4）让新形状立即重分类生效。

5. **受力/力矩**（`ComputeSolidLoads`，[testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L928-L1002)）
   - 基于格点 flag 而非形状，**无需改动**。

> **难度（限一个）**：★★☆☆☆（中偏易）。改动集中在一个判据函数 + 一处绘制 + 一个参数枚举，流固耦合管线完全复用。

### 2.3 多物体正式方案（组合 A）—— ≈ ★★☆☆☆

> 多物体**正式采用组合 A**：全局单一形状（可切换）+ 物体互不重叠 + 不旋转 + 固定上限 4 个 + 仅鼠标拖动。组合 A 砍掉的恰好是完整版的全部难点（重叠归属、持续 ghost 刷新、逐物体形状/旋转），实现难度与"单物体 + 一层遍历"相当。以下为可直接照做的实现清单。

#### S1 数据结构（组合 A 版）

```cpp
const int kMaxBodies = 4;                      // ④ 固定上限

struct RigidBody {
    float x, y;      // 中心位置
    float vx, vy;    // 壁面速度（每步 = 位移 / stepsPerFrame）
    float tx, ty;    // 目标点（鼠标/键盘写入）
    float radius;    // 半径；Box 为半宽=半高
    bool selected;   // 鼠标/UI 选中态（拖动 + 高亮）
};
```
- `LbmApp`：`std::array<RigidBody, kMaxBodies> bodies; int bodyCount = 1; int selectedBody = 0;`
- **全局形状**：`ObstacleShape obstacleShape;`（功能 1 的切换对象，所有物体同形状）；不设 `angle`（③ 不旋转）。
- 删除旧字段 `obstacleX/Y/TargetX/Y/VelocityX/Y`；`Init()` 中 `bodies[0] = { definition->obstacleStartX, definition->obstacleStartY, 0, 0, definition->obstacleRadius, true };`

#### S2 形状判据（全局 shape，无 angle）

```cpp
bool IsObstacleCell(ObstacleShape shape, int x, int y,
                    float cx, float cy, float radius) {
    const float dx = x - cx, dy = y - cy;
    switch (shape) {
    case Circle:  return dx * dx + dy * dy <= radius * radius;
    case Diamond: return fabsf(dx) + fabsf(dy) <= radius;
    case Box:     return fabsf(dx) <= radius && fabsf(dy) <= radius;
    }
    return false;
}
```
- 单物体 = `IsObstacleCell(obstacleShape, x, y, bodies[0].x, bodies[0].y, bodies[0].radius)`。

#### S3 统一格点分类（union，互不重叠 ⇒ 无歧义）

```cpp
bool IsAnyObstacleCell(const RigidBody* b, int count,
                       ObstacleShape shape, int x, int y) {
    for (int i = 0; i < count; i++)
        if (IsObstacleCell(shape, x, y, b[i].x, b[i].y, b[i].radius))
            return true;
    return false;
}
```
- 组合 A 保证互不重叠 ⇒ 每格点至多命中一个物体，union 判定无归属歧义。
- 1024² 时先算各物体包围盒 `[cx±r]×[cy±r]`、只在这些区域做判据；96×192 下可省略。

#### S4 `ApplyObstaclePose` 多物体化（唯一动流固耦合处）

- 签名改为 `ApplyObstaclePoses(const float newX[], const float newY[], const float wallUx[], const float wallUy[])`（数组长度 = bodyCount）。
- 内部流程**与单物体逐行一致**（全量重分类 → released/solid → 释放重建 → 新增 solid 写壁面矩 → touched → `SyncCellsToDevice`，[testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L735-L893)），只改两处：
  1. **分类**：`IsDemoCaseObstacleCell(...)` → `IsAnyObstacleCell(bodies, bodyCount, obstacleShape, x, y)`；
  2. **新增固体格点写壁面矩**：先反查所属物体，再取该物体的壁面速度：

```cpp
int OwnerBodyOfCell(const RigidBody* b, int count,
                    ObstacleShape shape, int x, int y) {
    for (int i = count - 1; i >= 0; i--)    // 互不重叠 ⇒ 命中唯一
        if (IsObstacleCell(shape, x, y, b[i].x, b[i].y, b[i].radius))
            return i;
    return -1;
}
// 写壁面矩处：
//   const int owner = OwnerBodyOfCell(bodies, bodyCount, obstacleShape, sx, sy);
//   writeBoundaryMoments(solidIdx, neighbor, wallUx[owner], wallUy[owner]);
```
- **不需要**"持续 ghost 刷新 / 重叠归属"——这是组合 A 的核心收益。
- 结束后更新每个物体的 `x/y/vx/vy`。释放判定基于 flag，与物体数量无关，原样保留。

#### S5 受力分组

- `ComputeSolidLoads`：对每个"固体邻居"执行 `owner = OwnerBodyOfCell(...)`，累加到 `bodyForceX[owner]/bodyForceY[owner]/bodyTorque[owner]`；力矩参考点由固定 `(obstacleX, obstacleY)` 改为 `bodies[owner].x/y`（对应现有 [testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L990-L992) 一处替换）。
- 平滑滤波按物体：`bodyForceX[i] += blend * (raw - bodyForceX[i])`。
- 面板显示：选中物体一行（`bodies[selectedBody]`）即可，无需 4 行全列。

#### S6 移动与拖动

- 键盘方向键（现有 `UpdateObstacleTarget`）：目标改为 `bodies[selectedBody].tx/ty`。
- 鼠标拖动（功能 2 §3.3）：命中遍历 → `selectedBody = i` → `WM_MOUSEMOVE` 写 `bodies[i].tx/ty`。
- `AdvanceObstacle` → `AdvanceObstacles()`：对每个物体循环"目标逼近 + `kMaximumWallSpeed` 限速 + `move/stepsPerFrame` 换算"（原逻辑 [testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L895-L926) 套循环即可）。
- **互不重叠校验（①，约 10 行）**：更新 `tx/ty` 后，若与其它物体中心距离 < `r_i + r_j`，把目标点沿连线推回最近合法位置，否则拒绝更新。

#### S7 绘制与 UI

- 绘制：遍历 bodies，按 `obstacleShape` 画轮廓（复用 §2.2 步骤 3 的分支）；`selected` 物体描边高亮。
- UI（功能 3）：物体数量 `+/-`（加物体时校验不重叠）、选中列表（单选）、全局形状下拉、每物体位置/半径滑块。

> **实现顺序**：S1 → S2/S3 → S4（先让多个静态物体正确参与流场）→ S6 拖动 → S5 受力 → S7 UI。每个小步都可编译可演示。

### 2.4 组合 A 的选择依据与未来升级路径

**为什么是组合 A**：完整版 ★★★★ 的难度全部来自 S3/S4/S5 的三个细节——重叠归属、持续 ghost 刷新、逐物体形状/旋转。组合 A 用"互不重叠 + 全局形状 + 不旋转"直接消灭它们，使多物体的 FSI 正确性与单物体几乎一致。

**从组合 A 升级到完整版**（按需解锁，成本递增）：

| 需求（出现时再开） | 解锁方式 | 难度增量 |
| --- | --- | --- |
| 不同物体不同形状 | 全局 `obstacleShape` 移进 `RigidBody`（每物体 shape 字段）+ UI 逐物体选择 | +★ |
| 物体需要旋转（方块翻转、后续鱼/风筝） | 加 `angle`、坐标旋转变换、壁面速度加 `ω×r` 项 | +★ |
| 物体允许重叠/密集摆放 | 加重叠归属规则（最后遍历者优先）+ 持续 ghost 刷新 | +★★（难度最大项） |
| 运行时动态增删物体 | `std::array` 改回 `std::vector` | +0.5★ |
| 逐物体受力同时显示 | 遍历显示 4 组力/力矩 | +0.5★ |
| 键盘同时控制多个物体 | 方向键 + `Shift`+方向键切换物体 | +0.5★ |

> 结论：本期**不预留**上述升级接口（YAGNI），等真实需求出现再按表解锁。

## 3. 功能 2：鼠标拖动场内物体

### 3.1 需求
- 鼠标按住物体直接拖动；分别评估"限一个"与"多个"难度。

### 3.2 实现步骤（单个物体）

1. **命中检测**：`WM_LBUTTONDOWN` → 光标转格点坐标 → `IsAnyObstacleCell(bodies, bodyCount, obstacleShape, gx, gy)` 命中（或距离 ≤ r + 3 格容差）→ `dragging = true`（单物体时同样适用）。
2. **拖动**：`WM_MOUSEMOVE` 时若 `dragging` → `bodies[0].tx/ty = clamp(光标格点)`（clamp 范围沿用现有 margin 逻辑，[testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L715-L723)）。
3. **运动执行**：**完全复用**现有 `AdvanceObstacle()` 的"目标逼近 + `kMaximumWallSpeed` 限速 + `stepsPerFrame` 换算壁面速度"机制（[testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L895-L926)），无需新物理。
4. **释放**：`WM_LBUTTONUP` → `dragging = false`，物体停在当前位置。
5. **与键盘共存**：方向键与鼠标都写同一组目标点，按时间顺序自然覆盖。

> **难度（限一个）**：★★☆☆☆（中偏易）。命中检测 + 消息映射约 60 行，运动复用现有管线。

### 3.3 实现步骤（多个物体，组合 A）

1. 命中检测遍历 `bodies`（从上到下 / 最近优先），选中最先命中者 → `selectedBody = i`。
2. 拖动只更新选中物体的 `tx/ty`，其余物体静止。
3. 被选中物体高亮绘制（描边变色），释放后恢复。
4. 运动执行复用 §2.3-S6 的 `AdvanceObstacles()` 逐物体循环（目标逼近 + 限速 + 互不重叠校验）。

> **难度（多个）**：★★☆☆☆（中偏易）。组合 A 下增量仅是"命中遍历 + 选中态管理"（约 40 行），不再依赖高难度系统（对比：完整版多物体才是 ★★★★）。

### 3.4 简化方案
- 一次只允许拖动一个物体（推荐，无多物体并行拖动的复杂度）。
- 拖动时若鼠标移到 UI 面板区域（`panel` 矩形内）则忽略，避免与功能 3 控件抢事件。

## 4. 功能 3：运行时自定义参数 UI（多预设 + 保存/读取）

### 4.1 需求
- 运行时调整参数；内置多套预设（两个 case 及其带/不带烟雾的组合）；支持读取/保存参数文件。

### 4.2 参数生效路径（关键设计）

| 参数类别 | 例子 | 生效方式 |
| --- | --- | --- |
| 直接生效（每帧被读取） | 入口速度、扰动、jetWidth、colorMax、stepsPerFrame、烟雾参数 | UI 写 `gApp.definition` 后下一帧自动生效 |
| 需同步设备 | `viscosity`（核内读 `mlflow[0].vis_shear`，见 [mrLbmSolverGpu2D.cu](file:///d:/Code/CG/Phy/home2d/inc/2D/gpu/mrLbmSolverGpu2D.cu#L75-L77)） | 新增 `SyncFlowScalarsToDevice()`：小 memcpy 更新设备端 `mrFlow2D.vis_shear` |
| 需重建算例 | nx/ny、初始条件、物体摆放 | 调用现有 `Release + Init`（会丢失流场，可接受） |

### 4.3 预设系统
```cpp
struct CasePreset {
    const char* name;      // "Karman", "Karman+Smoke", "Jet", "Jet+Smoke"…
    DemoCaseId id;
    DemoCaseDefinition def; // 默认参数
    bool smokeEnabled;     // 是否带烟雾（功能 4 开关）
};
```
- 内置预设表：`karman / karman+smoke / jet / jet+smoke / custom`（custom = 当前 UI 修改后的运行态）。
- 切换预设 = 拷贝 `def` + `smokeEnabled` 到运行时实例；若 nx/ny 变化则重建，否则热更新。

### 4.4 保存 / 读取
- 文件格式：`params.ini`，`key=value` 每行一项（**不引入 JSON 库**，保持工程零依赖）：
  ```

  smokeEnabled=1
  ```

## 5. 功能 4：烟雾交互模式

### 5.1 需求理解（四条规则的组合）
1. **拖动物体时**：物体整体作为"移动烟源"，其覆盖格点持续冒烟，烟雾被流场带走 → 物体拖出烟尾迹。
2. **无物体 + 鼠标滑动**：采用"交互式烟雾画笔与力源工具"（原创意 A：画烟/刮烟/吹风/旋涡）。
3. **关闭烟雾效果**：鼠标滑动（未按下）不产生任何烟雾。
4. **左键保持按下**：即使关闭烟雾效果，左键点击**仍可交互**（拖物体 / 吹风 / 旋涡等力源工具始终可用）。

### 5.2 交互状态机（与功能 2 合并实现）
```
鼠标移动(未按下) ─ smokeEnabled? → 画笔 hover 效果（画烟）
                └ 否则 → 无操作
左键按下 ─ 命中物体? → 拖动物体 + 物体冒烟(若 smokeEnabled)
        └ 未命中 → smokeEnabled? → 画笔/力源工具（画烟/吹风/旋涡）
                 └ 否则 → 力源工具（吹风/旋涡，不生成烟雾）
左键保持 → 每帧持续执行当前工具（注入/力）
左键释放 → 工具结束
```
- 说明：规则 4 由"力源工具不依赖 smokeEnabled"满足——左键交互（拖/吹/旋涡）始终有效，仅"烟雾生成"受开关控制。

### 5.3 实现步骤
1. `smokeEnabled` 布尔（功能 3 预设的一部分）。
2. **物体冒烟**：拖动期间每 UI 帧向物体覆盖格点 `smoke[idx] += rate`。格点集可直接用 `ApplyObstaclePoses`（§2.3-S4）收集的 solidCells 缓存，或遍历 `IsAnyObstacleCell` 求交；静止时按 UI 选项决定"持续冒烟 / 停止"。
3. **画笔/力源工具**（原"创意 A：Flow Brush"设计）：
   - 左键画烟、右键刮烟（`smoke[idx] *= 0`）、`Shift`+左键吹风（写 `forcex/forcey`）、中键旋涡。
   - **所有"鼠标→体力"写入必须带上限裁剪**（参考 `kMaximumWallSpeed`），防止局部速度过冲致流场发散。
4. 工具选择：功能 3 UI（当前工具下拉、笔刷半径、注入率、吹风强度）。
5. 调用位置：`WM_MOUSEMOVE/LBUTTON*` 处理器内更新"目标格点/是否按下"，`Step()` 前的 `ApplyMouseEffects()` 每帧统一执行注入/力写入（保证与 LBM 步解耦、顺序一致）。

> **难度**：★★★☆☆（中）。烟雾场、鼠标输入、物体系统均为已建基础设施；新增的是"状态机 + 物体冒烟注入"，难点在交互手感与数值稳定性（上限裁剪）。

### 5.4 简化方案
- 先只做"左键画烟 + 拖物体冒烟"，刮烟/吹风/旋涡作为第二批（它们是同一写入路径，按需添加）。
- 物体冒烟频率：每帧注入比每 LBM 步注入便宜且效果差异小，先每帧。

## 6. 功能 5：Ctrl 区域放大 + 格点调试信息

### 6.1 需求
- 按住 `Ctrl`：进入选中模式；左键单击某格点 → 显示该格点**全部数据与调试信息**，直接**覆盖绘制在流场表面**；松开 `Ctrl` 后调试信息消失。
- 附带"选中某块区域并放大"能力（放大镜 / 局部放大视图）。

### 6.2 实现步骤

1. **Ctrl 跟踪**：`WM_KEYDOWN/WM_KEYUP` 的 `VK_CONTROL` → `bool ctrlHeld`。
2. **选中格点**：`ctrlHeld && WM_LBUTTONDOWN` → 光标转格点坐标，记录 `debugCellX/Y`。
3. **数据读取**：host 端 `flow->fMom[idx*6+0..5]`（rho/ux/uy/pixx/piyy/pixy）、`flow->flag[idx]`、坐标与 `iteration` 每帧在 `CopyMomentsFromDevice` 后即最新。
   - 注意：`forcex/forcey` 的 host 值不一定与设备同步（设备端每次核迭代后更新）。调试信息**默认不显示 force**，或把 force 加入 `CopyMomentsFromDevice`（增加一次 D2H 拷贝，代价小，按需取舍）。
4. **覆盖绘制**：`Render()` 中在 `DrawField` 之后、`DrawPanel` 之前插入 `DrawDebugOverlay()`：
   - 半透明黑底矩形 + `DrawText` 多行文本（`x, y, flag名, rho, ux, uy, pixx, piyy, pixy, iteration`）。
   - 用现有位图字体（[testMrLBM2D.cpp](file:///d:/Code/CG/Phy/home2d/src/testMrLBM2D.cpp#L1216-L1227)），无需新字体。
   - `!ctrlHeld` 时跳过绘制（信息自动消失）。
5. **区域放大**（两种方案，A 更简）：
   - **A. 局部放大镜（推荐）**：Ctrl 模式下以光标为中心，把 field 纹理的 `±8` 格子区域用更大的 quad 绘制到画面角落——仅需修改 `glTexCoord` 子区域 + 固定大小 quad，**约 30 行，无新数据**。
   - **B. 框选放大**：Ctrl+拖动框选矩形，选中区域填满画面（改 `glOrtho` + 纹理坐标），交互稍复杂，留作可选。

### 6.3 难度评估
> **★★☆☆☆（中偏易）**。调试信息本身是"读数组 + 画文本"；放大镜是纯渲染层的纹理子区域绘制。风险点仅在 force 数据的设备/主机一致性，按 §6.2-3 取舍即可规避。
